# Review Changes

Review with a risk-first approach.

## Workflow

1. Identify what changed and which execution paths it affects.
2. Check the highest-risk files and functions first.
3. Look for missing tests, weak validation, and behavior drift.
4. Evaluate whether the change aligns with the current milestone and stated scope.
5. Report findings in severity order with concrete fixes.

## Output

- Critical issues
- Important improvements
- Suggestions
- Merge recommendation or residual risk note
