## Session 2: M23 SHARC Radiance Cache

### Session Duration
~3 hours

### Goals
- Implement SHARC (Spatially Hashed Radiance Cache) as M23
- Cache secondary bounces to cut render time
- Add Russian Roulette path termination
- UI controls + heatmap AOV

### What I Did

**Phase 1: Core data structures** (`radiance_cache.rs` — NEW)
- `CacheEntry` `#[repr(C)]` GPU-compatible (24 bytes)
- `RadianceCacheConfig` with cell_size, buffer_size, min_samples, max_age, min_bounce_depth, ema_weight
- `RadianceCache` with 64 sharded `RwLock<Vec<CacheEntry>>`
- Spatial hash: position quantized to cells + dominant-axis normal (6 dirs)
- `auto_cell_size()` from scene AABB
- 14 unit tests (determinism, normal disambiguation, cell quantization, round-trip, min_samples, staleness, concurrency, clear, disabled)

**Phase 2: Renderer integration** (`renderer.rs`)
- Added `radiance_cache: Option<Arc<RadianceCache>>` to `RenderConfig`
- Cache READ in bounce loop: after hit, before NEE (bounce >= min_bounce_depth, non-delta only)
- Cache WRITE after NEE: stores surface-local radiance (emission + NEE contribution)
- Extracted `local_radiance` var from existing NEE code (was adding directly to `accumulated`)
- Same integration in both `ray_color()` and `ray_color_with_aovs()`
- Added `cache_samples: u32` to `AovData` for heatmap

**Phase 3: Russian Roulette** (`renderer.rs`)
- After bounce >= 3: `survival_prob = max_component(throughput).min(0.95)`
- Random termination with `throughput /= survival_prob` survivor boost
- Unbiased — expected value unchanged

**Phase 4: IPR + Batch plumbing**
- `IvarState`: added `radiance_cache`, `radiance_cache_config`, `cache_heatmap_buffer`
- Cache created on scene build completion, cleared on `reset_accumulation`
- `advance_frame()` called between progressive passes
- Batch: per-frame `cache.clear()` for animated geometry
- `BucketResultWithAovs`: added `cache_samples` field

**Phase 5: UI + Heatmap AOV**
- `AovChannel::CacheHeatmap` variant with black→red→yellow→green colormap
- egui collapsing "SHARC Cache" section: enable/disable, cell_size (log slider), buffer size dropdown, min_samples, min_bounce_depth
- Live cache stats: hit rate %, occupancy %
- Config changes rebuild cache immediately

**Phase 6: Docs**
- MILESTONES.md: M23 repurposed from dissolved "Renderer Polish"
- SESSION_HANDOFF.md: updated with SHARC details
- GI_ID_METHOD.md: deduplicated (was 4x pasted content → single clean doc)

### Learnings
- `i32 as u32` cast in Rust handles negative coords same as GPU `bitcast<u32>(i32(...))` — important for hash consistency
- Sharded locking (64 shards) is simple and effective for rayon — threads rarely contend
- EMA vs running average: EMA weights recent samples more, better for dynamic scenes. Running average converges smoother for static. Went with EMA as default.
- Russian Roulette alone adds variance, but combined with SHARC the terminated paths fall back to cache data — strictly better than either alone
