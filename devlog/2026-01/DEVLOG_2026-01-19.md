# Development Log - 2026-01-19

## Session Focus

Fix UV and normal handling for faceVarying primvars, texture V-flip

## What I Did

### 1. Fixed faceVarying UV Interpolation

**Problem:** Coconut textures looked wrong - flat color instead of detailed texture

**Root Cause Discovery:**

- USD primvars can have different interpolations: `vertex`, `faceVarying`, `uniform`
- faceVarying UVs are indexed by face-vertex position, not vertex index
- Original code assumed vertex interpolation for all UVs

**Fix:**

- Check `stPrimvar.GetInterpolation()` for UV primvar
- For faceVarying: split vertices at UV seams
- Map (vertex_index, uv) -> new_vertex_index to deduplicate
- Only creates new vertices where UVs differ (seams), not full unindexing

### 2. Fixed faceVarying Normal Interpolation

**Problem:** Normals were indexed by vertex when they should be indexed by face-vertex

**Fix:**

- Check `mesh.GetNormalsInterpolation()`
- For faceVarying: index normals by face-vertex position
- For vertex: index by vertex index (original behavior)

### 3. Added V-Flip for Texture Sampling

**Problem:** Textures appeared wrong even with correct UVs

**Root Cause:** UV coordinate system mismatch

- USD uses bottom-left origin (OpenGL convention)
- Many textures expect top-left origin

**Fix:**

- Flip V coordinate in shader: `1.0 - in.uv.y`

## Learnings

### USD Primvar Interpolation

- `vertex` - one value per vertex, indexed same as positions
- `faceVarying` - one value per face-vertex corner (like OpenSubdiv)
- `uniform` - one value per face
- `constant` - one value for entire mesh

### UV Seam Handling

- Same vertex can have different UVs on different faces (seams)
- Must split vertices at seams or unindex mesh
- Quantize UVs when comparing (avoid float precision issues)

### Texture Coordinate Systems

- OpenGL/USD: origin at bottom-left, V increases upward
- DirectX/many images: origin at top-left, V increases downward
- Simple fix: `v = 1.0 - v` in shader
