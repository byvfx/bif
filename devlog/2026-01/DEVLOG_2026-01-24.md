# Development Log - 2026-01-24

## Session Duration
~2 hours

## Goals
- Implement subprocess-based .tx texture conversion (Arnold/Karma model)
- Wire up GUI button for pre-conversion
- Fix OIIO crashes on Windows

## What I Did

### Subprocess .tx Conversion (`bif_maketx`)
- Created `crates/bif_maketx/` standalone binary that wraps `bif_core::oiio::make_tx`
- Runs as isolated subprocess so OIIO SEH crashes don't take down main app
- `TextureCache::make_tx_subprocess()` finds binary next to exe, spawns with input/output args
- Cleans up partial .tx files on failure, returns success bool

### TextureCache API Refactor
- Renamed `auto_convert_tx` to `prefer_tx` (defaults to `false`)
- Load path: if `prefer_tx && .tx exists && newer than source` → load .tx, else load original
- No auto-conversion at load time — matches Arnold/Karma workflow
- Added `convert_textures_to_tx(&self, paths: &[String]) -> usize` for batch pre-conversion

### GUI "Convert to .tx" Button
- Added `ConvertTexturesToTx` event to `NodeGraphEvent`
- Added button + status to Ivar Render node (separator below Render button)
- Shows "Converting .tx..." during conversion, then "N/M converted" or "All up to date"
- Conversion runs in background thread via `tx_conversion_receiver` channel
- Gated behind `#[cfg(feature = "oiio")]`, shows "OIIO not available" without feature

### C++ Bridge Hardening
- Added try/catch to `oiio_load_texture` and `oiio_load_texture_with_mips`
- Prevents C++ exceptions from crossing FFI boundary (won't catch SEH though)

### Viewport Texture Loading Cleanup
- Removed `auto_convert_tx = false` overrides from texture_loader.rs and lib.rs
- Viewport path uses `prefer_tx: false` (no .tx needed, uploads to. GPU directly)
- Serialized OIIO loading (iter vs par_iter) remains for thread safety

## Issues Found
- OIIO `make_texture` causes SEH crash on Windows → solved by subprocess isolation
- OIIO `load_texture_with_mips` also crashes on .tx files on Windows → left `prefer_tx: false` for now
- Corrupt leftover `Bark.tx` from previous crash caused secondary crash → deleted, subprocess now cleans up partials
- The .tx files ARE created successfully by subprocess, but OIIO can't read them back (SEH in load)

## Current State
- .tx conversion works via subprocess (13 textures converted successfully)
- Ivar render works with OIIO loading originals + in-memory mipmaps
- HDRI/IBL via GPU compute works
- Viewport loads textures without .tx
- "Convert to .tx" button functional but .tx files not consumed until OIIO read-back is fixed

## Learnings
- Windows SEH exceptions (access violations) bypass C++ try/catch entirely
- OIIO on Windows has issues with both `make_texture` and reading .tx files back
- Subprocess isolation is the right pattern for crash-prone native code
- Arnold/Karma model: pre-convert as separate step, renderer picks up if available
