## What I Did

### Export Fixes (3 bugs found and fixed)

1. **cloud.prototype_ids not set** — PointInstancer compute updated cloud.name but not prototype_ids. Added `cloud.prototype_ids = vec![pid]` in render.rs.

2. **starts_with('/') guard skipping BIF protos** — export.rs skipped writing meshes when proto.name started with '/'. But Primitive nodes with prim_paths (e.g. `/World/Cube1`) set the proto name to a '/'-prefixed path. Removed the guard — all referenced protos now get written.

3. **Standalone meshes not exported** — export_scene only wrote meshes referenced by point clouds. A Primitive → UsdExport chain (no Scatter/Instancer) produced no mesh. Added a second pass that writes all prototype meshes not already written by the instancer loop.

### CompositeProvider (Live Scene Graph)

- `ProceduralPrim` struct — path, type_name, vertex/triangle/point counts, prototype refs
- `CompositeProvider` — merges USD stage + working_scene into unified PrimDataProvider
  - Prototypes → Mesh prims, Point clouds → PointInstancer prims
  - Auto-generates intermediate Scope prims for path hierarchy
- Wired into scene browser and selection handling in render.rs
- Property inspector shows vertex count, triangle count, point count, prototype refs

- `crates/bif_core/src/usd/export.rs` — remove starts_with guard, add standalone mesh loop

## Learnings

- Proto name vs prim_path collision: when Primitive node sets proto.name from prim_path, it breaks the `/`-prefix heuristic that distinguished BIF vs USD protos. Better approach: explicit source flag on Prototype struct (future).
- Export needs to handle both instancer-referenced and standalone meshes. The original code only handled the instancer case.
- Compared BIF export output with Houdini's USDA — Houdini wraps meshes in Xform hierarchy with kind metadata.
