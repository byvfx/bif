### Progressive Ivar Viewport (Feature)

Replaced one-shot full-SPP render with progressive accumulation:

- Added `accumulation_buffer`, `accumulated_samples`, `target_spp` to `IvarState`
- New `PassComplete` message variant and `reset_accumulation()`/`needs_more_passes()`/`is_pass_in_flight()` methods

- Refactored `start_ivar_render()` into setup + `start_progressive_pass()` (1 SPP per pass)
- `poll_ivar_messages()` accumulates beauty into running sum, divides by pass count for display
- Main loop: auto-starts next pass when idle, camera/transform changes reset accumulation
- UI: SPP progress bar, per-pass bucket progress, target SPP slider (1-256)

## Issues Found

- Borrow checker: `poll_ivar_messages()` couldn't assign `receiver = None` while receiver was borrowed → fixed by collecting messages into Vec first
- Pre-existing test: `test_camera_source_display` expected "Viewport" but `display_name()` returns "Perspective" → fixed
- `pass_number` field broke 4 explicit `RenderConfig` construction sites → added `pass_number: 0` to each

## Learnings

- Collecting mpsc messages into Vec before processing avoids borrow conflicts when the handler needs to mutate the receiver field
- Progressive accumulation is simple: running sum / N, with pass_number XORed into RNG seed for different noise each pass
- AOVs (depth, normal) only need first pass — no benefit from accumulation

## Session 2 — Interactive Ivar Navigation Preview

### Duration

~30 min

### Goals

- Eliminate black viewport during camera orbit/pan in Ivar mode

### What I Did

Implemented progressive resolution refinement for Ivar navigation:

1. **IvarState fields** — `current_scale`, `interaction_scale` (default 4), `last_interaction_time`, `settle_timeout_ms` (300ms)
2. **`restart_ivar_at_scale(scale)`** — Restart render at reduced resolution without BVH rebuild. Recreates texture + bind group at scaled size.
3. **Render loop rewrite** — 3-state machine: INTERACTING (1/N res) → SETTLING (double res every 300ms) → FULL-RES PROGRESSIVE
4. **Sampler → Nearest** — `FilterMode::Nearest` for blocky pixelated upscale at reduced res (identical at 1:1)
5. **Nav Quality slider** — UI slider mapping exponent 1-3 → scale 1/2, 1/4, 1/8
6. **Transform drag** — Property inspector drag uses interaction scale instead of bare `reset_accumulation`
7. **Camera at resolution** — `create_ivar_camera_at_resolution(w,h)` so progressive passes use scaled dimensions

### Key Files (4)

- `ivar_state.rs` — 4 new fields + defaults
- `ivar_build.rs` — `restart_ivar_at_scale()`, `create_ivar_camera_at_resolution()`, `poll_scene_build` update, scaled camera in `start_progressive_pass`
- `render.rs` — settle timer logic, UI slider, drag integration, mode switch init
- `lib.rs` — sampler Nearest

### Learnings

- `trailing_zeros()` on power-of-2 u32 gives the exponent — clean bidirectional slider mapping
- Texture recreation at 240x135 is near-free; no need to optimize repeated restart during orbit
- Progressive refinement only needs to gate on `current_scale == 1` to prevent accumulation at wrong resolution
