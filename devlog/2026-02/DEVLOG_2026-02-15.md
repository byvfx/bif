## What I Did

### Point Instancer Node

- Added `SceneNode::PointInstancer` variant with `instance_count` + `is_instanced` fields
- 2 inputs (points from Scatter, proto from Primitive/UsdRead), 1 output (scene)
- `resolve_input_connection()` helper reads snarl wiring — first real use of connections

- `NodeGraphEvent::PointInstancerCompute` carries node_id + both source node IDs

### Renderer Integration

- `instancer_results: HashMap<NodeId, Vec<Instance>>` stores expanded instances separately
- Event handler: resolve cloud_id + proto_id from maps, clone cloud, set prototype, expand, store
- `reload_working_scene()` appends instancer instances to transform/material/GPU arrays
- DeleteNode cleanup removes instancer results + reloads scene

### Bug Fixes

1. **Combined mesh buffer overflow**: Baking instancer instances into combined VB exceeded 1GB GPU limit. Fix: instancer uses multi-draw (per-prototype VB + instance transforms) only.
2. **Culling manager buffer overflow**: `update_visible_instances()` wrote all visible instances to GPU buffer without capacity check. Fix: added `max_instances` field, clamp near+far writes to buffer capacity.

### Files Changed

- `node_graph.rs` — PointInstancer variant, event, UI, helper, toolbar, 2 tests
- `lib.rs` — `instancer_results` field
- `render.rs` — PointInstancerCompute handler, DeleteNode cleanup
- `scene_loader.rs` — append instancer instances in reload_working_scene
- `culling_manager.rs` — buffer overflow fix with max_instances clamp

## Learnings

- Baking N mesh copies into one vertex buffer is O(N *mesh_size) — hits GPU limits fast. Multi-draw with instance transforms is O(mesh_size + N* transform_size).
- The culling manager had a latent buffer overflow bug that only manifested with large instance counts from the instancer. Always guard GPU buffer writes with capacity checks.
- `InPin` doesn't implement `Copy` — need to collect pins into Vec for reuse in tests.
