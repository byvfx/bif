### Performance Investigation (Major Win)
Initial load time for spaceship scene: **117 seconds**

Added C++ profiling with `<chrono>` to identify bottleneck:
```
[USD_BRIDGE]   Resolver context: Xms
[USD_BRIDGE]   UsdStage::Open(): Xms
[USD_BRIDGE]   cache_stage_data(): Xms
[USD_BRIDGE]   cache_prim_data(): Xms
[USD_BRIDGE]   cache_animation_data(): Xms
```

**Root cause found:** Per-mesh/per-keyframe `std::cout` and `fprintf(stderr,...)` logging. Windows console I/O is extremely slow.

With 921 meshes and potentially 350 keyframes each, thousands of console writes were happening.

### Fix Applied
Removed verbose C++ logging:
- Per-mesh vertex/face counts
- Per-keyframe position output
- Per-subset material info
- UV/normal interpolation logs
- Camera matrix debug output

## Learnings

1. **Console I/O is a killer** - Windows console output is orders of magnitude slower than expected. Never log per-item in hot loops.

2. **Profile before optimizing** - Adding timing instrumentation immediately revealed the bottleneck was I/O, not USD parsing or mesh processing.

3. **C++ `<chrono>` pattern** - Simple and effective:
   ```cpp
   using namespace std::chrono;
   auto start = high_resolution_clock::now();
   // ... work ...
   auto ms = duration_cast<milliseconds>(high_resolution_clock::now() - start).count();
   ```

4. **Rust timing pattern** - Similar simplicity:
   ```rust
   let start = std::time::Instant::now();
   // ... work ...
   let ms = start.elapsed().as_secs_f64() * 1000.0;
   ```
