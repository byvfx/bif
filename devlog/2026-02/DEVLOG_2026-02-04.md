## What I Did

### Root Cause Analysis

The play button wasn't advancing animation properly because `PresentMode::Mailbox` allowed unlimited FPS (~700fps), causing tiny delta_time values (~1.4ms vs expected 16ms). While the math was correct, the visual experience was inconsistent.

### Solution: Wall-Clock Time Playback

Replaced delta-time accumulation with wall-clock elapsed time:

1. **New TimelineState fields:**
   - `playback_start_instant: Option<Instant>` - when playback started
   - `playback_start_frame: f64` - frame at playback start
   - `realtime: bool` - toggle for wall-clock vs every-frame mode

2. **New methods:**
   - `play()` - Start playback, record wall-clock start
   - `pause()` - Stop playback, clear instant
   - `toggle_playback()` - Toggle between states
   - `update()` - Calculate frame from elapsed wall-clock time
   - `reset_playback_anchor()` - Reset anchor when scrubbing

3. **Realtime toggle (like Houdini):**
   - **ON (default):** Wall-clock accurate at scene FPS, may skip frames
   - **OFF:** Every frame sequentially, as fast as possible

4. **PresentMode change:**
   - Changed `Mailbox` → `Fifo` for proper VSync
   - Reduces CPU/GPU waste, consistent 60fps

5. **UI updates:**
   - Play button uses `toggle_playback()` instead of direct toggle
   - Slider resets playback anchor when scrubbed during playback
   - Added "RT" checkbox with tooltip

6. **Tests:**
   - `test_wall_clock_playback` - Frame advances with elapsed time
   - `test_loop_playback` - Seamless looping
   - `test_pause_stops_time` - Pause freezes playback
   - `test_non_realtime_mode` - Every-frame mode works
   - `test_scrub_during_playback` - Continues from scrubbed position

### Files Modified

- `crates/bif_viewport/src/lib.rs` - TimelineState, update_animation, UI
- `SESSION_HANDOFF.md` - Updated status

## Learnings

1. **Wall-clock time is robust:** Delta-time accumulation is fragile when frame rate varies wildly. Wall-clock calculation gives consistent results regardless of FPS.

2. **VSync matters for animation:** `Mailbox` present mode allows unlimited FPS which can cause animation issues. `Fifo` gives proper 60fps capping.

3. **Houdini's realtime toggle is smart:** Having both wall-clock (for preview) and every-frame (for checking each frame) modes covers all use cases.

## Session 3: 4K HDRI IBL Performance Fix

## Duration

~30 min

## Goals

- Fix 4K HDRI IBL generation stall

## What I Did

- Refactored `compute_ibl.rs` to batch all GPU submissions
- 7 separate `queue.submit()` → 1 single submission
- Renamed `dispatch_*` → `encode_*` methods taking shared `CommandEncoder`
- Optimized RGBA: pre-allocated Vec vs flat_map().collect()

## Changes

- `crates/bif_viewport/src/compute_ibl.rs`
  - `generate()`: single encoder for all passes
  - `encode_equirect/irradiance/prefilter()`: take &mut CommandEncoder
  - `upload_equirect()`: Vec::with_capacity + extend_from_slice

## Learnings

- Multiple GPU queue.submit() cause sync stalls on large workloads
- Batching compute passes into single submission = big perf win
