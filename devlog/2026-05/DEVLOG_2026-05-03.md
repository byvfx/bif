### Fix: UNC paths on Windows SMB drives
`cpp/usd_bridge/usd_bridge.cpp` was converting `\\server\share\...` to `//server/share/...` at two sites, breaking USD's AR on Windows. Added guard to skip the backslash→slash replacement when path starts with `\\`.

### Fix: USDA attribute metadata placement
USDA requires attribute metadata (`interpolation = "faceVarying"`) AFTER the value array, not before the `=`. Fixed in two places in `comp_base.usda` and one in `scene/geo.usda`.

### primvars:displayColor Vulkan fallback
Meshes like `WavePlane` and PointInstancer scatter prototypes had display color in IVAR (vertex colors path) but rendered grey in Vulkan because the renderer uses a per-triangle material table.

Fix:
- `MeshData.display_color: Option<[f32; 3]>` — stores first color from `primvars:displayColor`
- `scene_loader.rs` sentinel injection site — creates a synthetic `bif_core::Material` per prototype when `display_color` is present but no material binding exists; appends synthetic materials after the default-grey slot in the GPU table so IVAR indices are unaffected

## Learnings
- `primvars:displayColor` is a Hydra display hint, not a UsdPreviewSurface input. BIF's Vulkan path uses its own material table — no automatic fallback from USD.
- Windows UNC `\\server\share` cannot be represented as `//server/share` for USD's AR. The `std::replace` guard is the minimal fix without restructuring path normalization.
- USD USDA text format: attribute metadata must come AFTER the value, e.g. `float[] foo = [1,2] (interpolation = "vertex")`.
