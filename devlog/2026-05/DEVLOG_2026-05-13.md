# Development Log - 2026-05-13

## Session Duration

~1 hour.

## Goals

Follow-ups on yesterday's AOV viewer ship — user reported the Ivar/Vulkan toggle was missing and asked for a way to disable the default blue sky background.

## What I Did

- **Render-mode picker.** Found that `RenderMode::Ivar` only got set inside `trigger_ivar_render`/`render_dispatch.rs:10` with no path back to `Vulkan` — explains the "couldnt find it" report. Added `Renderer::render_mode()`/`set_render_mode(mode)`, four invokables on `BifShellState` (`render_mode_count` / `render_mode_name_at` / `active_render_mode_index` / `on_select_render_mode`), and a `mode_picker` `QComboBox` in the breadcrumb row right of the AOV picker. Entries "Live (Vulkan)" / "Ivar". The render-settings "Ivar Render" button is unchanged — it still kicks off a fresh batch; the picker just controls which surface is shown.
- **Headlight toggle false start.** First read of "turn off the default light" pointed at the WGSL headlight fallback in `basic.wgsl:386`. Extended `EnvironmentParamsUniform` from 16 → 32 bytes (`headlight_enabled: u32` + 3 pad u32s), updated both `basic.wgsl` and `skybox.wgsl` structs, gated the headlight `else` branch on the new flag, added `EnvironmentManager::set_headlight_enabled` + `Renderer::headlight_enabled`/`set_headlight_enabled`. Build + tests + clippy all green. User clarified — they meant the blue sky-gradient, not the headlight (which already auto-disables when scene lights exist).
- **Reverted the headlight wiring** in one sweep: struct back to 16 bytes, both wgsl shaders restored, `EnvironmentManager` setters deleted, `Renderer` setters renamed.
- **Sky-gradient toggle.** `IvarState::use_sky_gradient` (default `true`) already existed and was already plumbed into the `RenderConfig` at pass start (`ivar_build.rs:724`). Added `Renderer::sky_gradient_enabled()`/`set_sky_gradient_enabled(bool)` thin wrappers, swapped the invokable names (`sky_gradient_enabled` / `on_set_sky_gradient_enabled`), and renamed the C++ `QCheckBox` to "Sky Gradient". Defaults to ON to preserve current behavior; flipping off makes escaped Ivar rays return `RenderConfig::background` instead of the white→blue ramp at `bif_renderer/src/renderer.rs:423`.

## Key Decisions

- **One commit, three controls.** AOV viewer (from 2026-05-12) + render-mode picker + sky-gradient toggle all share the breadcrumb-row surface and the same cxx-qt invokable pattern. Coherent v0.16.5 docket drop.
- **Don't ship the headlight uniform.** Even though it built and tested clean, the user feedback redirected and the headlight already auto-disables on scene lights. Reverting keeps the EnvironmentParamsUniform at 16 bytes — no shader-side wiring left behind for a feature we're not surfacing.
- **Reused existing `use_sky_gradient` state.** The plumbing was already there; only the UI was missing. Avoided introducing parallel state.

## Learnings

- **Always ask "what do you actually see?" before plumbing.** I plumbed the WGSL headlight before confirming what the user meant by "default light." The `IvarState::use_sky_gradient` was a one-line wrapper away the whole time. Cost ~20 minutes of revertable wiring.
- **cxx-qt invokable pattern scales.** Three different controls (combo, combo, checkbox) all wire through the same `count` / `name_at(i)` / `active_index` / `on_select(i)` (or `getter` / `on_set`) pattern. No custom signals, no QObject subclassing, no MOC dance. Following the established `camera_picker` pattern made each new control ~20 lines on each side.
