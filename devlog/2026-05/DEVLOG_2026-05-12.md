## Key Decisions
- Refresh_node is *defensive*: only repopulates an empty cached subtree, never replaces an existing one. Mid-walk subtree mutation in QTreeView has surprising selection-state interactions — left non-empty refreshes to the standard `fetchMore` path.
- Path-format normalization done C++-side (`path_matches`) rather than at the Rust qprop boundary. Pragmatic — single call site, no surface area on the Rust side.
- Side observation: "viewport selection only lets me select a couple things" likely stems from invisible meshes polluting the pick BVH after commit `e55b3d6` removed the load-time skip. Same root cause as Bug 2. Deferred.

## Learnings
- `QAbstractItemModel::rowCount(parent)` typically returns 0 for non-zero parent columns by convention — must navigate the tree via column 0 even when reading column-agnostic roles like PathRole.
- `children_populated = (child_count == 0)` in `make_node` is an optimization that can lock a node into a fake-leaf state if the data source returned 0 transiently. Lazy-load caches need an explicit invalidation path.
