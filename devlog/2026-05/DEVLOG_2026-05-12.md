## Key Decisions
- Refresh_node is *defensive*: only repopulates an empty cached subtree, never replaces an existing one. Mid-walk subtree mutation in QTreeView has surprising selection-state interactions — left non-empty refreshes to the standard `fetchMore` path.
- Path-format normalization done C++-side (`path_matches`) rather than at the Rust qprop boundary. Pragmatic — single call site, no surface area on the Rust side.
- Side observation: "viewport selection only lets me select a couple things" likely stems from invisible meshes polluting the pick BVH after commit `e55b3d6` removed the load-time skip. Same root cause as Bug 2. Deferred.

## Learnings
- `QAbstractItemModel::rowCount(parent)` typically returns 0 for non-zero parent columns by convention — must navigate the tree via column 0 even when reading column-agnostic roles like PathRole.
- `children_populated = (child_count == 0)` in `make_node` is an optimization that can lock a node into a fake-leaf state if the data source returned 0 transiently. Lazy-load caches need an explicit invalidation path.

## Key Decisions
- Save As writes via `export_layer_as_string` + `std::fs::write` (text USDA only). Binary `.usdc` path needs an `SdfLayer::Export` bridge function — deferred to v0.17 when the `cpp_bridge.rs` split lands. Dialog filter is `*.usda` only for now so users don't get confused by an extension that won't work.
- C++ opens the dialog (matches `trigger_open_stage` pattern), Rust handles the write. Avoids round-tripping the entire QDialog state through cxx-qt.
- Qt-level integration test punted in favor of bif_core-level coverage. QApplication-under-cargo-test on Windows isn't worth the yak shave for this PR.
- First assertion in the Save As test (`post_working.identifier == working_id`) was wrong-conceptually — `SceneLayerState::from_stage` re-derives the working layer from the stage rather than reading prior state. Dropped the assertion and documented the export-only guarantee as a comment instead, since it's enforced at the Qt invokable layer.

## Learnings
- `MutexGuard` temporaries extend lifetime to the end of the enclosing match expression — when that's the tail expression of a closure, the guard outlives variables captured before. Fix: bind the match to a `let` so the guard drops before closure locals.
- `SceneLayerState::from_stage` doesn't honor a previously-set edit target — it rebuilds working-layer from scratch. Tests asserting "working layer survives X" need to assert at the stage's edit-target level, not via a re-construction of state.
- `clippy::question-mark` rewrites `let Some(x) = ... else { return None; }` → `let x = ...?;` — easy follow-up after refactor.
