### Fixes Applied (commit `ddf0e49`)

**Critical:**
1. GPU resource thrashing — was creating new texture/view/bind_group every frame during camera drag. Now skips recreation when dimensions unchanged.
2. Render loop ordering — settle timer checked `is_pass_in_flight()` before messages were polled, causing stale state. Moved poll_scene_build + poll_ivar_messages before settle timer.

**Important:**
3. Integer division aspect ratio drift — `vp_w / scale` truncates, causing aspect ratio jumps across refinement steps. Now uses `(vp_w / scale as f32).round()`.
4. Deduplicated `start_ivar_render` / `restart_ivar_at_scale` — `start_ivar_render` now delegates to `restart_ivar_at_scale(1)`, removing ~30 lines of duplicate logic.
5. Replaced `interaction_scale` (power-of-2) with `interaction_quality` (exponent) — eliminates fragile `trailing_zeros()` reverse mapping. Added `interaction_scale()` helper method.
6. Resize handler missing state reset — added `current_scale = 1` and `last_interaction_time = None` in `resize()`.

**Improvements:**
7. Skip AOV buffer allocation at reduced scale — alpha/depth/normal buffers not useful at 1/8 res.
8. Shorter settle timeout for coarse refinement — 150ms for scale>=4, 300ms for medium→full.
9. Added 7 unit tests for progressive refinement state machine.

## Learnings
- GPU texture allocation during rapid interaction (60+ fps) causes allocation pressure — always check if dimensions changed before recreating
- Render loop ordering matters for state machines with settle timers — poll completion before checking timers
- Integer division for resolution scaling causes aspect ratio drift at non-power-of-2 viewport sizes
- `trailing_zeros()` is fragile for reverse-mapping power-of-2 values — store the exponent directly
