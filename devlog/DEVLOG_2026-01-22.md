1. **Phase 3 modules use free functions** - `texture_loader`, `ivar_renderer`, and `frustum_culling` use free functions with explicit parameters instead of methods. More testable and clearer dependencies.

3. **Kept tightly-coupled methods in Renderer** - Functions like `build_ivar_scene`, `start_ivar_render`, `poll_ivar_messages` access many Renderer fields; extracting them would require 10+ params. Left as methods.

## Session 2: Ivar Texture/Shader Integration

### Session Duration
~2 hours

### Goals
- Hook up textures to Ivar path tracer (5-phase plan)

### What I Did

Implemented full texture/shader integration for Ivar across 5 phases:

#### Phase 1: UV + Normal Interpolation
- Added `uv_data`, `normal_data` to `EmbreeScene`
- Interpolate per-vertex UVs/normals using barycentrics in `hit()`
- Extract UVs/normals from `mesh_data.vertices` in world build

#### Phase 2: Texture Loading
- Added `scene_materials`, `texture_base_dir` to viewport state
- Create `TextureCache` on build thread
- Use `DisneyBSDF::from_material_with_textures()` instead of `From<&Material>`

#### Phase 3: Per-Triangle Materials (Multi-Material)
- Removed generic `M` from `EmbreeScene<M>` → concrete `EmbreeScene`
- Changed `material: Arc<M>` → `materials: Vec<Arc<DisneyBSDF>>` + `triangle_material_ids: Vec<u32>`
- Lookup per-triangle material in `hit()` via `triangle_material_ids[prim_id]`

#### Phase 4: Opacity Maps
- Added `opacity: f32` + `opacity_texture: Option<Arc<Texture>>` to `DisneyBSDF`
- Added `opacity_texture: Option<String>` to `bif_core::Material`
- Stochastic alpha cutout in `scatter()`: random pass-through when opacity < 1

#### Phase 5: Normal Mapping
- Added `tangent`, `bitangent` to `HitRecord`
- Compute per-triangle tangents from edge/deltaUV in `EmbreeScene::new()`
- Interpolate + Gram-Schmidt orthogonalize tangent in `hit()`
- `apply_normal_map()` in `DisneyBSDF`: TBN matrix transform of sampled normal
- Removed `#[allow(dead_code)]` from `normal_texture`

### Files Changed
- `crates/bif_renderer/src/embree.rs` - UV/normal/tangent interpolation, multi-material, removed generic
- `crates/bif_renderer/src/disney.rs` - opacity, normal mapping, `apply_normal_map()`
- `crates/bif_renderer/src/hittable.rs` - tangent/bitangent fields on HitRecord
- `crates/bif_renderer/src/triangle.rs` - test fixes (new HitRecord fields)
- `crates/bif_renderer/src/sphere.rs` - test fixes (new HitRecord fields)
- `crates/bif_viewport/src/lib.rs` - scene_materials, texture_base_dir, multi-material build
- `crates/bif_core/src/scene.rs` - opacity_texture field on Material
- `crates/bif_core/src/usd/loader.rs` - opacity_texture: None in Material construction

### Design Decisions

1. **EmbreeScene non-generic** - Holds `Vec<Arc<DisneyBSDF>>` directly. No need for trait object indirection since Ivar only uses DisneyBSDF.

2. **Stochastic opacity** - Random pass-through rather than deterministic alpha blend. Converges with more samples, simpler to implement, physically motivated.

3. **Gram-Schmidt for tangent** - Orthogonalize interpolated tangent against shading normal before computing bitangent. Prevents skewed TBN frames from non-orthogonal interpolation.

4. **Per-vertex tangents from UV deltas** - edge/deltaUV method per triangle, stored per-vertex (3 per tri). Degenerate UVs fall back to `Vec3::X`.

### Learnings

- Barycentric interpolation: `w = 1-u-v`, attribute = `w*a0 + u*a1 + v*a2`
- Embree `rtcGetGeometryUserData` returns geometry-level user data, not per-instance
- Removing a generic type param from a struct requires updating all trait impls, constructors, and call sites
- Tangent computation can produce NaN if UV deltas are zero; needs fallback
