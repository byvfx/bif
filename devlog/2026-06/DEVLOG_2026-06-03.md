## What I Did
Started as a quick "is the vcpkg 404 fix right?" check; turned into a full
**release-pipeline bring-up**. The tagged-release job had never produced a
working artifact since the v0.15.0 Qt migration — it always died at vcpkg
first, masking everything downstream. Peeled the onion one wall at a time,
each verified via a throwaway `v0.0.0-ci-test` tag:

1. **vcpkg zlib 404** — stale `vcpkgGitCommitId` baseline `a42af01` had dead
   upstream download URLs. Bumped to `d015e31` (vcpkg 2026.05.25) + added
   matching `builtin-baseline` to `vcpkg.json`.
2. **`QtMissing`** — cxx-qt build script panicked; runner had no Qt. Added
   `jurplel/install-qt-action@v4` (Qt 6.8.3, `win64_msvc2022_64`).
3. **USD missing** — `build.rs` silently skips the USD bridge without
   `pxr/pxr.h`; `vcpkg.json` only had `openimageio`. Added `usd`.
4. **`find_package(OpenImageIO)` fail** — `run-vcpkg` manifest mode installed
   to a GUID `vcpkg_installed` dir, but `build.rs`/packaging assume the classic
   `$VCPKG_ROOT/installed` layout, and the bridge sub-CMakes flipped to manifest
   mode on discovering the repo `vcpkg.json`. Fix: classic-mode install +
   `-DVCPKG_MANIFEST_MODE=OFF` on both bridge configures.
5. **LNK1181 embree4.lib** — Embree is a vcpkg package (`bif_renderer/build.rs`)
   never added to the install list. Added `embree[geometry-triangle,geometry-instance]`.
6. **LNK1181 zlib.lib** — newer vcpkg renamed zlib's import lib `zlib.lib` → `z.lib`.
   Made `build.rs` probe for whichever exists (local older vcpkg still resolves
   `zlib.lib`).
7. **Runtime DLL gap** — downloaded the built artifact and inspected it:
   `embree4.dll` + OIIO codec deps were absent (hand-picked copy list). Switched
   Package step to bulk-copy all vcpkg DLLs.

Added **vcpkg binary caching** (`x-gha`) so the one-time USD/OIIO source build
(~40 min) is reused — later iterations were ~10 min.

**Files:** `.github/workflows/ci.yml`, `vcpkg.json`, `crates/bif_core/build.rs`.

## Learnings
- **Cargo feature unification** — `oiio`/`oidn` reach the Qt UI's render path
  even though `bif_qt` declares no such features; enabling them at the
  top-level binary (`bif_viewer`) is enough. Run `bif_viewer`, not `bif_qt_shell`.
- **vcpkg manifest vs classic mode** matters a lot: manifest auto-detection
  walks *up* from the CMake source dir, so a repo-root `vcpkg.json` hijacks
  sub-builds. `-DVCPKG_MANIFEST_MODE=OFF` is the cure for "consume prebuilt libs".
- **Pin-version drift** bites: hardcoded import-lib names (`zlib.lib`,
  `OpenEXR-3_4`) break when the vcpkg baseline moves. Probe, don't hardcode.
- **"The step ran" ≠ "the artifact works"** — Package succeeded but the zip was
  missing `embree4.dll`. Always inspect the artifact.
