## Goals

- Get Embree subdivision surface rendering working end-to-end

## What I Did

- **Embree subdivision rendering** — debugged and fixed the full pipeline from USD → C++ bridge → Rust FFI → Embree:
  - Fixed `RTCBufferType` enum values: Face was 7 (should be 16), EdgeCreaseIndex was 8 (should be 18), EdgeCreaseWeight was 9 (should be 19). This was the root cause of `RTC_ERROR_INVALID_ARGUMENT`.
  - Added `vertices_orig` FFI field to pass original pre-UV-split vertex positions from C++ bridge. UV seam splitting reorders/expands vertices, breaking polygon index references.
  - Added `rtcInterpolate` FFI with `RTCInterpolateArguments` struct (not `rtcInterpolate0` which is an inline wrapper).
  - Smooth normals via `rtcInterpolate` on Vertex buffer — computes limit surface partial derivatives (dPdu × dPdv) for mathematically exact smooth normals.
  - Tessellation rate 8 via `rtcSetGeometryTessellationRate` for BVH accuracy. Rate controls micro-triangle density; normals come from rtcInterpolate so rate mainly affects ray intersection precision. 4 for preview, 8 default, 16+ production.
  - Skipped UV vertex attribute buffer when UV count != position count (faceVarying UVs need separate topology — deferred).
- **Two-sided viewport lighting** — added normal flip in `basic.wgsl` when normal faces away from camera. Fixes dark surfaces on meshes with inconsistent winding (not subdiv-specific).
- **Diagnostic logging** — per-buffer Embree error checks, face topology validation, subdiv setup summary.
- **Test asset** — `pig_subDivCrease_test.usd` from Houdini (2889 faces, 2886 verts, catmullClark).

## Issues Found

- Embree FFI enum values for subdivision buffer types were wrong (copied from Embree 3 values, not Embree 4).
- UV seam splitting in C++ bridge completely rebuilds vertex arrays — original vertex order is lost. Had to add `vertices_orig` FFI to preserve originals.
- `rtcInterpolate0` is an inline C++ wrapper, not an exported symbol — must use `rtcInterpolate` with args struct.
- faceVarying UVs (common for subdiv meshes) can't be used as per-vertex attribute buffers — need separate topology support (deferred).
- Pig mesh from Houdini has inverted normals in viewport regardless of subdivisionScheme — pre-existing winding issue, fixed with two-sided lighting.

## Learnings

- Embree 4 subdivision evaluates the exact Catmull-Clark limit surface — no iteration count needed. Tessellation rate only affects BVH granularity.
- `rtcInterpolate` on Vertex buffer returns smooth partial derivatives (dPdu, dPdv) — cross product gives mathematically exact limit surface normals.
- Embree 4 buffer type enum values differ significantly from Embree 3 — always verify against the actual header.
- UV seam splitting is destructive to vertex ordering — must preserve originals at the C++ level for any code that needs the original topology.
