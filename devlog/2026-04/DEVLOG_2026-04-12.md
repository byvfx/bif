2. **Python ground truth** — enhanced `scripts/dump_rigid_meshes.py` pattern into a temp script that resolves each rigid mesh's skeleton-global joint index via `UsdSkelSkinningQuery::ComputeJointInfluences` + skeleton joint-order lookup.

   Findings on `HumanFemale.walk.usd` (22 rigid meshes):

   - **Eyes** (`Pupil_sbdv`, `Iris_sbdv`, `Sclera_sbdv`, `Cornea_sbdv`): `elem_size=1, w=1.0` — single joint (LEye/REye).
   - **Shoes** (`HeelSeam_sbdv`, etc.): `elem_size=1, w=1.0` — single joint (LFoot/RFoot).
   - **Hair** (all `Shell_sbdv` layers): **`elem_size=3, w=0.333`** — 3 neck/head bones weighted 1/3 each.
   - **Fingernails** (`ThumbNail_sbdv`, etc.): **`elem_size=2, w=0.5`** — 2 finger-tip bones weighted 1/2 each.

### Root cause

`SkinKind::Rigid` compression in `crates/bif_core/src/usd/loader.rs:276` extracted only `joint_indices.first()` and `joint_weights.first()`. For hair: `(joint=5 [Head], w=0.333)`. The skinning kernel did `M·p·0.333`, collapsing each hair vertex toward the Head bone's origin by 2/3. The mesh still animated with the skeleton (single correct joint) but appeared spatially shrunk — exactly matching the visible "offset."

The compression was introduced in v0.13.5.2 (commit `b61264e`) and inherited into v0.13.6-dev. Single-joint rigid meshes (eyes, shoes) kept working; multi-joint rigid meshes (hair, nails) broke silently.

### Fix

`crates/bif_core/src/usd/loader.rs` — gate the compact encoding on `element_size == 1`:

```rust
let is_rigid_compact = skin_data.is_rigid && skin_data.element_size == 1;
let kind = if is_rigid_compact {
    SkinKind::Rigid { joint_idx, weight }
} else if skin_data.is_rigid {
    // Broadcast the single authored block × N verts → SkinKind::PerVertex
    ...
} else { /* existing per-vertex path */ };
```

The multi-joint rigid branch broadcasts the `element_size`-sized block across `mesh.positions.len()` post-split vertices, producing the same layout the C++ bridge emits for non-rigid meshes. The skinning kernel then runs its normal weighted-blend inner loop and correctly sums the 3-bone / 2-bone contributions.

## Learnings

- **USD `IsRigidlyDeformed()` is about per-prim binding, not single-joint.** A mesh where every vertex shares the same influence block is "rigidly deformed" regardless of how many joints contribute — uniform multi-bone bindings are legal and common (hair, cloth segments, fingernails with tip-interpolation rigs).
- **Compression assumptions need a gated condition.** The `SkinKind::Rigid { joint_idx, weight }` variant is a great memory win for the common case but it silently mis-encoded the uncommon case. Ship the compression together with the discriminating check (`element_size == 1`) in the same commit next time.
- **Single-joint rigid meshes masked the bug for months.** Shoes and eyes looked fine in visual tests; the bug only surfaced on characters with multi-bone hair or rigs. Always test accessories when touching the skinning path.
- **Diagnostic ladders pay off.** Starting with the math equivalence test immediately ruled out the skinning kernel and pointed at loader classification. The Python ground truth dump then closed the case in minutes.

The plan called for an LRU cache on `SceneLayerState::opinion_trace`. Implementing it cleanly requires interior mutability (`Mutex<LruCache>`), which breaks `Scene: Clone`. Kept `SceneLayerState` pure-data. If the UI surfaces perf issues, it can own a per-selection cache locally. Note captured.
