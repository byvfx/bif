## Learnings
- The right split is:
  - `agents/` = canonical source
  - `scripts/sync-agent-config.ps1` = wrapper/artifact projection
  - `scripts/install-codex-skills.ps1` = Codex-local install step
- Thin-wrapper architecture works as long as the bootstrap gap is documented honestly. Claude/Kilo can follow the pointer pattern directly; Codex needs either explicit bootstrap or an installed repo-generated skill.
- For Codex specifically, `sync` is not enough. The real chain is:
  - edit canonical doc
  - sync generated artifact
  - install generated artifact
  - use skill

## What I Did
- Added a cached selected-prim stack snapshot on `BifShellState` so the Qt property inspector no longer re-fetches the full prim stack for every composition-arc row.

- Gated the Qt timeline `QTimer` so playback pauses while the app is hidden/minimized/inactive and resumes when the app is active again.
- Reworked the Qt scene browser model to lazy-populate children one level at a time via `hasChildren` / `canFetchMore` / `fetchMore`.
- Prevented the demo tree from re-seeding after a real stage has been loaded once and later closed.
- Bumped release-facing docs and split `CHANGELOG.md` for `v0.15.0`.
- Bumped the workspace package version to `0.15.0` so `BIF_QT_VERSION` matches the shipped release.
- Repaired the release validation suite by replacing deleted HDR fixtures with self-contained test data and updating stale USD/export readback tests to load payload-backed caches before asserting on meshes, instancers, materials, or lights.

- Release handoffs need one more repo-state sanity pass than normal implementation plans; version metadata and release docs can drift independently of the feature code.
