# Development Log - 2026-04-27

## Session Duration
~2 hours

## Goals
- Make C4a dogfood usable by adding a Qt viewport path for moving selected prims.
- Verify transform edits author to the working layer and save cleanly.

## What I Did
- Added a wgpu line-overlay translate gizmo for selected viewport instances.
- Routed Qt mouse hover, LMB axis press, drag preview, and release into the viewport renderer.
- Reused the C4a `TransformEdit` path so release records undo and authors to the active USD working layer when a stage is loaded.
- Preserved existing USD xform op types when saving movement, so `xformOp:translate` receives a vec3 instead of a matrix.
- Fixed the outline shader uniform padding that made wgpu reject the selected-outline pass.
- Kept Alt+LMB orbit, MMB pan, wheel zoom, and LMB selection behavior intact.

## Issues Found
- The old transform controls were still egui-only, so Qt had backend edit support but no artist-facing way to move prims.
- Synthetic `/BIF/.../<instance>` paths needed display-path normalization before tree or viewport selections could resolve gizmo instances.
- USD rejects matrix values on translate ops; the bridge now extracts translation vectors for translate-backed prims.
- The Qt relationships tab is still a placeholder and should be restored before broader C4b dogfood.

## Current State
- Select a prim in the viewport or scene tree, click-drag a colored axis handle, then `Ctrl+S` to save the working layer.
- Dogfood confirmed the gizmo appears, moves prims, and no longer trips the USD translate type mismatch.
- Relationship editing/inspection is still not implemented in Qt.

## Learnings
- Keep transform authoring in `bif_viewport::Renderer`; Qt should only forward physical-pixel mouse events.
- `SceneInstances::prim_paths` can be synthetic loader paths, so selection UI paths need normalization at the renderer boundary.
- USD xform edits must preserve the authored op type instead of blindly reusing the first op with a matrix.
