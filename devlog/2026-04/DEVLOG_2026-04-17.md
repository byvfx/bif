## Learnings

- **QSS stylesheet composition with dynamic colors**: `QString::fromLatin1(...).arg(...)` chains work but the `%1..%10` placeholder order matters. Got tripped once by reordering `.arg()` calls; once the `%` tokens were numbered explicitly, it stabilized.
- **`breadcrumb_set_path` + pill coexistence**: when a widget API's refresh pattern is "clear everything", adjacent permanent widgets need to live in a sibling layout, not inside the cleared container. Cheap but easy to miss.
- **Piggybacking signals**: `layer_state_revisionChanged` is a useful catch-all for "stage/layer world just shifted" — using it instead of minting separate signals for stage-path / edit-target kept the signal graph tight.
- **`is_anonymous && is_muted` isn't the real writability check** — `SdfLayer::PermissionToEdit()` is. Landing the pragmatic version now and deferring the FFI to Tier 1.5 kept momentum; the distinction won't bite until a user opens a stage where the root layer is read-only-baked (rare but real on studio published assets).

## Late session — 3 bugfixes (animation playback + load reset + color dots)

User-reported: (1) timeline plays but animated prims stay frozen, (2) opening a second USD shows old prims, (3) scene browser layer color dots are missing. Three small fixes, one commit:

### 1. Animation playback doesn't update the viewport

**Root cause:** `Renderer::update_animation` was the eval loop but it was only called from the deleted egui frame loop. Phase F removed the call site without rewiring. Qt's QTimer advances `current_frame` qproperty, the slider sets it on scrub, but the value never propagates into `Renderer::timeline_state.current_frame`.

**Fix:** Extracted the eval body of `update_animation` into `apply_animation_at_current_frame()`. Added `Renderer::set_time(frame: f64)` that sets `timeline_state.current_frame = frame` then calls the helper (skipping the wall-clock advance that `update_animation` does). Added cxx-qt invokable `BifShellState::on_frame_changed(frame: i32)` that calls `with_viewport_mut(|vp| vp.renderer_mut().set_time(frame as f64))`. Connected `current_frameChanged` → `on_frame_changed` in `window_builder.cpp` so both QTimer-driven playback and slider drags propagate.

The 0.5-frame `last_evaluated_frame` tolerance guards against re-eval storms.

### 2. Loading a second USD shows leftover prims

**Root cause:** `Renderer::load_usd_scene` doesn't fully evict prior `SceneManager` state up front; the second open ran on top of a non-clean slate. Viewport showed stale instances from the previous stage.

**Initial fix attempt** inlined the close-stage teardown (`wait_for_gpu` + `scene = SceneManager::new()` + `rebuild_pick_scene()`) at the top of `on_stage_path_opened`. User confirmed the viewport cleared but **the scene browser tree didn't** — old prims stayed in the panel.

**Real root cause:** scene browser routes through `with_scene_browser_provider` which builds a `CompositeProvider` from BOTH `scene.usd_stage` AND `nodes.cached_scene_graph`. The inline teardown reset the USD half but `nodes.cached_scene_graph` and friends survived (`nodes` is a separate `Renderer` field). Between the bumped revision signal and the next `render()` tick that would rebuild the cache, the model saw new USD prims merged with stale procedural cache.

**Final fix:** added `Renderer::reset_scene_state()` to bif_viewport — single source of truth for "evict the previous stage entirely". Drains GPU, replaces `SceneManager`, clears all `nodes.*` caches (cached_scene_graph, instancer_results, node_proto/cloud maps, node_prim_counts, primitive_name_counters), bumps dirty flags, rebuilds pick BVH. Both `close_stage` (Ctrl+W) and the second-open reset call it. Also bumped scene_browser_revision + layer_state_revision after the reset so the model rebuilds against the empty state before new data lands (prevents a 1-frame visual flash of merged old+new tree).

**Latent bug closed:** `close_stage` had the same procedural-cache leak — Ctrl+W → reload would have shown the same bug. The shared helper closes both code paths.

### 3. Scene browser layer color dots are missing

**Root cause:** `populate_subtree` and `rebuild_from_state` in `scene_browser_model.cpp` passed `/*color_index=*/-1` for every row. The `PrimRowDelegate::paint` method only draws the dot when `color_index >= 0 && color_index < 8`, so the dots never rendered.

**Fix:** added `prim_color_index_at(path)` invokable that reads `SceneLayerState::layer_for_prim` (prim_path → strongest opinion source layer index, populated by `populate_layer_for_prim` after stage load) and returns the palette index mod 8. Both row builders now call it instead of hardcoding -1.
