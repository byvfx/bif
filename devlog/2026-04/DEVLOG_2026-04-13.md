## Learnings

- **cxx-qt vs plain cxx decision can defer.** The spike used plain `cxx` + `qt-build-utils` to isolate the wgpu-QWindow question from cxx-qt macro maturity. Phase A will commit to cxx-qt for Rust-side QObjects. Low-risk because cxx-qt is strictly a superset of cxx + Qt.
- **`/Zc:__cplusplus` is the first thing to add when MSVC meets Qt 6.** Without it, `qcompilerdetection.h` fatal-errors before any real C++ compiles.
- **`QT_NO_KEYWORDS` is optional and has real cost.** Without it, `signals:` and `emit` work normally; with it, every signal/slot declaration becomes `Q_SIGNALS:` / `Q_EMIT`. cxx-qt recommends defining it to avoid Rust keyword collision with `slots`. Phase A choice.
- **`paintEngine() const override { return nullptr; }`** is the key line that makes wgpu-in-QWidget work. Qt's raster engine never touches the widget, so wgpu owns the HWND's pixels entirely.
- **QWidget::winId() on Windows returns HWND directly** — no cast gymnastics. Wrap into `NonZeroIsize` → `Win32WindowHandle` → `RawWindowHandle::Win32`. `hinstance` comes from `GetModuleHandleW(nullptr)` on the C++ side.
- **QApplication lifetime + argc storage.** `QApplication(int&, char**)` keeps a reference to argc. Spike sidestepped Rust-side lifetime juggling by constructing `static char arg0[]; static int argc = 1;` in the C++ `qt_spike_run()`. Phase A/B can revisit.
