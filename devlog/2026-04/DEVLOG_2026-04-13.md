## Learnings

- **cxx-qt vs plain cxx decision can defer.** The spike used plain `cxx` + `qt-build-utils` to isolate the wgpu-QWindow question from cxx-qt macro maturity. Phase A will commit to cxx-qt for Rust-side QObjects. Low-risk because cxx-qt is strictly a superset of cxx + Qt.
- **`/Zc:__cplusplus` is the first thing to add when MSVC meets Qt 6.** Without it, `qcompilerdetection.h` fatal-errors before any real C++ compiles.
- **`QT_NO_KEYWORDS` is optional and has real cost.** Without it, `signals:` and `emit` work normally; with it, every signal/slot declaration becomes `Q_SIGNALS:` / `Q_EMIT`. cxx-qt recommends defining it to avoid Rust keyword collision with `slots`. Phase A choice.
- **`paintEngine() const override { return nullptr; }`** is the key line that makes wgpu-in-QWidget work. Qt's raster engine never touches the widget, so wgpu owns the HWND's pixels entirely.
- **QWidget::winId() on Windows returns HWND directly** — no cast gymnastics. Wrap into `NonZeroIsize` → `Win32WindowHandle` → `RawWindowHandle::Win32`. `hinstance` comes from `GetModuleHandleW(nullptr)` on the C++ side.
- **QApplication lifetime + argc storage.** `QApplication(int&, char**)` keeps a reference to argc. Spike sidestepped Rust-side lifetime juggling by constructing `static char arg0[]; static int argc = 1;` in the C++ `qt_spike_run()`. Phase A/B can revisit.

- **`src/theme.rs`** — port of `bif_viewport/src/theme.rs` to UI-agnostic `Color(u8, u8, u8, u8)` + `to_qt_rgba_string()` helper. - **`src/bin/bif_qt_shell.rs`** — Phase A/B dogfood binary. Deleted at Phase F.

### C++ side

- **`cpp/window_builder.h/.cpp`** — `extern "C" int bif_qt_run_shell()` constructs `QApplication` (static argc/argv) + `QMainWindow` (1440x900) + `BifShellState` parented to window + File/View/Help menu bar with Ctrl+N/O/S/Shift+S/Q/1-4/\\ accelerators + 4 `QDockWidget` placeholders (Scene Browser, Layer Stack on left; Property Inspector on right; Node Graph at bottom) + central viewport placeholder + status bar. Movable/floatable/closable docks.

### Compile iteration — 3 errors, all fixed

1. `impl qobject::BifShellState { ... }` INSIDE the bridge → "expected an empty impl block". Moved the impl outside the bridge (cxx-qt 0.7: `#[qinvokable]` declared in `extern "RustQt"`, implemented in a regular impl block outside).
2. `self.rust()` unresolved → missing `use cxx_qt::CxxQtType;` trait import for accessor method.
3. Link error `unresolved external symbol cxxbridge1$194$bif_qt_run_shell` → had plain `#[cxx::bridge]` in `app.rs` alongside the cxx-qt bridge. Cannot mix — `cxx_qt_build::CxxQtBuilder` only processes `#[cxx_qt::bridge]`. Merged the extern decl into the single cxx-qt bridge.

Plus two lint fixes: `# Safety` section added to `bif_qt_run_shell` doc; `#![allow(clippy::missing_safety_doc)]` at crate scope for the macro-expanded form clippy can't see.

### Verification

Launched `bif_qt_shell.exe` — 30 MB working set, correct title, all 4 placeholder docks visible and movable, menu bar interactive. User confirmed visually: "this works well." No crashes, clean exit on window close.

## Learnings

- **cxx-qt 0.7 `#[qinvokable]` vs plain cxx fn signatures.** Declared in `extern "RustQt"` inside the bridge, implemented in `impl qobject::TheObject { fn foo(...) }` OUTSIDE the bridge. Non-empty impl blocks inside the bridge are a compile error. This is opposite to how cxx works for plain `extern "C++"` types.
- **cxx-qt's `CxxQtType` trait is the gateway to Rust-side state.** `.rust()` for `&BifShellStateRust`, `.rust_mut()` for `&mut`. Must be in scope.
- **cxx-qt-generated include path convention:** `<crate_name>/src/<bridge_file>.cxxqt.h`. For our case: `bif_qt/src/main_window.cxxqt.h`.
- **Can't mix cxx + cxx-qt bridges in one crate.** `cxx_qt_build::CxxQtBuilder` only processes `#[cxx_qt::bridge]` modules. Any `#[cxx::bridge]` module's Rust↔C++ glue never compiles, manifesting as a link-time unresolved-external. Merge extern decls into one cxx-qt bridge.
- **`#![allow(clippy::missing_safety_doc)]` is needed at crate scope** for cxx-qt bridges. Clippy sees the macro-expanded function forms, not our `# Safety` doc comments on the declarations. Documenting anyway is still worth it for humans reading the source.
- **C++ continues to own widget tree assembly (QMainWindow/QDockWidget/QMenuBar) for Phase A**, not because cxx-qt can't do it but because cxx-qt-lib's QtWidgets wrappers are thin and the Rust boilerplate wouldn't pay off here. Phase B/C may revisit if Rust-side QObject adoption grows.

### B.3 — menu action wiring

- 5 `#[qinvokable]` methods on `BifShellState` (`on_new_stage`, `on_open_stage`, `on_save`, `on_save_as`, `on_about`). Phase B stubs — log + update `status_message`.

- Shortcuts: `QKeySequence::New/Open/Save/SaveAs` work on Windows. `QKeySequence::Quit` is empty on Windows — hardcoded `Ctrl+Q`. `Ctrl+1..4` for workspaces (stub), `Ctrl+\` for Zen.

### B.4 — Zen mode

- Checkable `Zen Mode` action; `QAction::toggled` lambda iterates `findChildren<QDockWidget*>()` and toggles visibility. Menu + status bar persist.

## Learnings

- **`extern "Rust"` and `extern "RustQt"` coexist** inside a `#[cxx_qt::bridge]` module. Only `#[cxx::bridge]` (plain) cannot.
- **`type Foo = path::Foo;` is rejected in `extern "Rust"`** — must be `type Foo;` resolved via parent-module `use`.
- **`QKeySequence::Quit` is empty on Windows** — hardcode `Ctrl+Q`.
- **`rust::Str` ↔ `QString` conversion**: `QString::fromUtf8(s.data(), static_cast<int>(s.size()))`.
- **`findChildren<QDockWidget*>()` on QMainWindow** returns every dock including floating — perfect for Zen.
- **cxx-qt `#[qinvokable]` methods are regular C++ methods on the QObject** — call directly from signal lambdas, no `QMetaObject::invokeMethod` needed.
- **Q_OBJECT C++ headers need three pieces**: `cc_builder.file(...)` for impl, `CxxQtBuilder::qobject_header(...)` for moc trigger, `cc_builder.include(...)` for include path.
