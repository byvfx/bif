## Learnings

- **cxx-qt vs plain cxx decision can defer.** The spike used plain `cxx` + `qt-build-utils` to isolate the wgpu-QWindow question from cxx-qt macro maturity. Phase A will commit to cxx-qt for Rust-side QObjects. Low-risk because cxx-qt is strictly a superset of cxx + Qt.
- **`/Zc:__cplusplus` is the first thing to add when MSVC meets Qt 6.** Without it, `qcompilerdetection.h` fatal-errors before any real C++ compiles.
- **`QT_NO_KEYWORDS` is optional and has real cost.** Without it, `signals:` and `emit` work normally; with it, every signal/slot declaration becomes `Q_SIGNALS:` / `Q_EMIT`. cxx-qt recommends defining it to avoid Rust keyword collision with `slots`. Phase A choice.
- **`paintEngine() const override { return nullptr; }`** is the key line that makes wgpu-in-QWidget work. Qt's raster engine never touches the widget, so wgpu owns the HWND's pixels entirely.
- **QWidget::winId() on Windows returns HWND directly** — no cast gymnastics. Wrap into `NonZeroIsize` → `Win32WindowHandle` → `RawWindowHandle::Win32`. `hinstance` comes from `GetModuleHandleW(nullptr)` on the C++ side.
- **QApplication lifetime + argc storage.** `QApplication(int&, char**)` keeps a reference to argc. Spike sidestepped Rust-side lifetime juggling by constructing `static char arg0[]; static int argc = 1;` in the C++ `qt_spike_run()`. Phase A/B can revisit.

## Learnings

- **cxx-qt 0.7 `#[qinvokable]` vs plain cxx fn signatures.** Declared in `extern "RustQt"` inside the bridge, implemented in `impl qobject::TheObject { fn foo(...) }` OUTSIDE the bridge. Non-empty impl blocks inside the bridge are a compile error. This is opposite to how cxx works for plain `extern "C++"` types.
- **cxx-qt's `CxxQtType` trait is the gateway to Rust-side state.** `.rust()` for `&BifShellStateRust`, `.rust_mut()` for `&mut`. Must be in scope.
- **cxx-qt-generated include path convention:** `<crate_name>/src/<bridge_file>.cxxqt.h`. For our case: `bif_qt/src/main_window.cxxqt.h`.
- **Can't mix cxx + cxx-qt bridges in one crate.** `cxx_qt_build::CxxQtBuilder` only processes `#[cxx_qt::bridge]` modules. Any `#[cxx::bridge]` module's Rust↔C++ glue never compiles, manifesting as a link-time unresolved-external. Merge extern decls into one cxx-qt bridge.
- **`#![allow(clippy::missing_safety_doc)]` is needed at crate scope** for cxx-qt bridges. Clippy sees the macro-expanded function forms, not our `# Safety` doc comments on the declarations. Documenting anyway is still worth it for humans reading the source.
- **C++ continues to own widget tree assembly (QMainWindow/QDockWidget/QMenuBar) for Phase A**, not because cxx-qt can't do it but because cxx-qt-lib's QtWidgets wrappers are thin and the Rust boilerplate wouldn't pay off here. Phase B/C may revisit if Rust-side QObject adoption grows.

## Learnings

- **`QSettings` persists per-application** (set by `setApplicationName` + `setOrganizationName`) — on Windows it's `HKCU\Software\BIF\BIF`. Workspace blobs live there as binary `QByteArray` values.
- **`QMainWindow::saveState() / restoreState()` serializes the dock layout + sizes + states** but NOT the dock contents. Object names on every dock are required for the restore to find them — already set in Phase A's `make_placeholder_dock`.
- **`restoreState` returns `bool`** — false means the saved blob is incompatible (e.g., dock object names changed). Always have a fallback default layout.
- **`QToolBar` doesn't propagate parent stylesheet to its child QToolButton instances** unless explicitly targeted via `QToolBar QToolButton`. Used inline stylesheet on the toolbar to fix.
- **`QSortFilterProxyModel::setFilterFixedString`** is exact substring; case sensitivity is configured separately. For fuzzy match (planned post-v0.15), need a custom QSortFilterProxyModel subclass overriding `lessThan` + `filterAcceptsRow`.
- **Borderless `QDialog` with translucent background** needs `Qt::FramelessWindowHint` + `Qt::WA_TranslucentBackground` + a stylesheet that paints `QDialog#objName` (background flows from the QSS background-color, not the window).
- **`QShortcut::setContext(Qt::ApplicationShortcut)`** is required for global shortcuts that should fire even when focus is in a child widget (e.g., a QLineEdit). Default is `Qt::WindowShortcut` which is fine for most.

## Checkbox Hit-Detection Bug

## Architecture Decision: Phase C skipped the AppEvent bridge

Panels mutate `BifShellState` directly via `#[qinvokable]` methods, not through the existing `EventBus`. Works for Phase C demo scope (state-only mutations with no render/geometry side-effects). ## Learnings

- **cxx-qt auto-generates `<name>Changed` signals for every `#[qproperty]`** — use these for cross-component refresh rather than declaring `#[qsignal]` methods. The revision-counter pattern (bump an i32 qproperty to broadcast "something changed") is a clean shortcut when you don't care about the specific change.
- **Custom tree delegates that shift paint rects MUST mirror the shift in `editorEvent`** or interactive elements (checkboxes, editors) go offset from their visual position. Captured in SESSION_HANDOFF.md gotchas.
- **Qt's QList/QVector require copy-constructible types** — std::vector is the escape hatch for move-only element types like unique_ptr. For cxx-qt interop this is strictly C++ side, doesn't leak to Rust.
- **`QSortFilterProxyModel::recursiveFilteringEnabled` is Qt 5.10+** but doesn't do what I want (shows children of matching parents, not parents of matching children). Hand-rolled `HierarchicalFilter` subclass does the right thing.
- **Clippy's `needless_arbitrary_self_type`** fires on impl-side `self: &Self` even when the bridge needs the explicit form — fix in impl, leave bridge alone.

## Compile Fixes Along the Way

- cxx-qt bridge rejects `&self` — needs `self: &BifShellState`. But impl body uses `&self` (clippy). Remember: bridge decl uses explicit `self: &T`, impl uses `&self`.
- `E0716 temporary value dropped while borrowed` on `let r = self.as_ref().rust();` — bind `pin_ref = self.as_ref()` first so the Pin outlives the `.rust()` borrow.
- `QObject::connect(from, signal, wire, lambda)` fails — `BifNodeWire` inherits `QGraphicsPathItem` (no QObject). Pass the sender node as context, or use 3-arg connect.
- Missing `qobject_header("cpp/render_settings_widget.h")` in build.rs → moc didn't run → linker errors on `metaObject/qt_metacast/qt_metacall`. Added.

## Learnings

- **`QGraphicsView` inside a plain `QWidget` doesn't forward wheel events upward.** Zoom handlers must live on the view. Same goes for key events if you want graph-specific shortcuts.
- **`QGraphicsObject` is the Q_OBJECT-inheriting graphics item base.** For nodes that emit signals on move, this is the right subclass. Wires (pure path items) don't need signals — `QGraphicsPathItem` is fine but can't be a connect target.
- **Middle-mouse pan via `ScrollHandDrag`** requires synthesizing a left-button event — QGraphicsView's built-in pan mode is wired only to `LeftButton`. The `QMouseEvent` copy-constructor with button swap handles this cleanly.
- **`beginResetModel/endResetModel` is heavy** but simpler than incremental `dataChanged` emits for panels that rebuild from scratch on state change. Fine for small models (layer stack, 10-node graph); Phase E should use fine-grained changes for the 100K-prim scene browser.
- **Qt's QSS cascades differently from HTML CSS.** Setting `QGroupBox { color: ... }` doesn't color the title — that needs `QGroupBox::title`. Took a couple iterations on Property Inspector group styles.

## Learnings

- **`ShortcutRegistry` pattern scales** — every shortcut introduced after Phase E.1 should go through it. Migrating the menu's existing shortcuts (Ctrl+N/O/S/etc.) to the registry is a one-liner each and lets the Preferences dialog find them uniformly.
- **QTimer interval retuning is just a pair of `*Changed` signal connections** — no need for a timer restart dance. Set interval while running and Qt respects it on the next tick.
- **Loop-mode as an enum** (Repeat/Bounce/Stop/Continue) is the natural evolution from the boolean we have now — in cxx-qt it becomes a `#[qenum]`-annotated enum on `BifShellState`, with the loop toggle button upgrading to a dropdown/menu.
- **Expanding QWidget spacers are how you do 3-zone alignment in a QToolBar** — it's not native, but the pattern is clean: `addWidget(spacer_with_Expanding_SizePolicy)` between zones.
- **A visually-dominant current-frame readout is a UX win** — orange color + bigger font + accent border makes the eye land on "what frame am I on?" instantly, which is the question you're asking 90% of the time you look at the timeline.
