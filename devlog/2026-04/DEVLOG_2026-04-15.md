### Renderer decoupling (`crates/bif_viewport/src/lib.rs`, `render.rs`)

**New Renderer API:**

- `pub fn new(surface, device, queue, config, size: (u32, u32), scale_factor: f32) -> Result<Self>`
  — synchronous; caller owns wgpu primitive construction.
- `pub fn attach_egui(&mut self, egui_state: egui_winit::State)` — optional
  egui overlay attachment. `bif_viewer` calls this; `bif_qt` will not.
- `pub fn egui_state_mut() -> Option<&mut egui_winit::State>` — caller drives
  the winit ↔ egui handshake (`take_egui_input`, `on_window_event`,
  `handle_platform_output`) outside this crate.
- `pub fn egui_ctx() -> &egui::Context` — for reading `pixels_per_point`,
  pushing theme, etc.
- `pub fn set_dialog_focus_hook<F: Fn(bool) + 'static>(&mut self, hook: F)`
  — installable visibility toggle for the Windows z-order workaround; the
  existing 5 internal `with_dialog_focus` call sites route through this. No
  change to dispatch modules.
- `pub fn scale_factor() -> f32` + `resize((u32, u32), f32)` — scale stored
  on Renderer, updated on resize.
- Constants `REQUIRED_FEATURES` + `required_limits()` exposed so callers can
  request the right wgpu device.

**Removed:** `handle_egui_event` (caller drives `egui_state.on_window_event`
directly), old `resize((u32, u32))` signature, `window: Arc<winit::Window>`
field, `egui_winit::State` construction in `new()`.

**`render()` signature change:**

```rust
// before
pub fn render(&mut self, clear_color: wgpu::Color, window: &winit::Window) -> Result<()>
// after
pub fn render(
    &mut self,
    clear_color: wgpu::Color,
    raw_input: Option<egui::RawInput>,
) -> Result<Option<egui::PlatformOutput>>
```

`raw_input: None` = headless (3D only), `Some` = egui overlay. `submit_gpu_frame`
destructures `FullOutput` and returns `PlatformOutput` for the caller to hand
to winit. All egui passes inside `submit_gpu_frame` conditionalized on
`full_output.is_some()`.

**Zero direct `winit::*` imports** in `lib.rs` and `render.rs`. Remaining
references are doc comments and the `egui_winit::State` type (held as
`Option<egui_winit::State>` — winit transitive dep is unavoidable while egui
is still alive, and acceptable).

### bif_viewer compat shim (`crates/bif_viewer/src/main.rs`)

Added `fn create_renderer(window: Arc<Window>) -> Result<Renderer>` free
function that:

1. Builds `wgpu::Instance` + surface + adapter + device + queue + config (the
   setup that used to live inside `Renderer::new`).
2. Calls `Renderer::new(...)`.
3. Builds `egui_winit::State` from the winit window and calls `attach_egui`.
4. Installs `set_dialog_focus_hook(move |v| window.set_visible(v))`.

Replaced the 3 `pollster::block_on(Renderer::new(window.clone()))` sites with
`create_renderer(window.clone())` (sync — `pollster::block_on` moved inside
the helper for the adapter/device requests).

Replaced `renderer.handle_egui_event(window, &event)` with an inline
`egui_state_mut().on_window_event(window, &event).consumed` check.

Replaced `renderer.render(clear_color, window)` with a 3-step sequence:
`take_egui_input(window)` → `render(clear_color, Some(raw_input))` →
`handle_platform_output(window, platform_output)`.

Updated both `resize` call sites to pass `window.scale_factor() as f32`.

## Learnings

- **Handoff scope estimates can hide winit-through-egui coupling.** The
  "pull Renderer into bif_qt" plan assumed a simple type swap. Real
  coupling was 8 touchpoints across 2 files, 5 of which were structurally
  through `egui_winit::State`. Explore agent's pass-through read caught this
  before I burned time on a dead end.
- **`with_dialog_focus` pattern is a great fit for an installable hook.** 5
  internal callers would've had to bubble set_visible out to bif_viewer; one
  `Box<dyn Fn(bool)>` closure field keeps all of them unchanged while making
  Renderer windowing-system-agnostic.
- **egui's per-frame winit handshake is conceptually small**
  (`take_egui_input` pre-frame, `handle_platform_output` post-frame). Passing
  `Option<RawInput>` in and returning `Option<PlatformOutput>` lets
  `bif_viewport` stay egui-aware without being winit-aware.
- **Destructuring `FullOutput` lets us move `platform_output` upstream** while
  consuming the other fields in-place. Important because the new contract
  returns platform_output to the caller (can't call `handle_platform_output`
  here anymore — no winit Window).
- **Pulling wgpu primitive construction into the consumer is the right move
  long-term.** bif_viewer and bif_qt can each use their native window-system
  surface creation; `Renderer::new` is now a pure wgpu consumer and doesn't
  need winit-vs-Qt conditionals.
