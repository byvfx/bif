## What I Did

### Selection outline rendering — full rebuild

- **Root cause 1 (z-fighting)**: `PolygonMode::Line` pipeline used `depth_compare: LessEqual` with `bias: constant=-2`. On DX12, `DepthBias = constant * 2^-24` ≈ 0 — effectively no bias, so gold lines z-fought with surface and never showed.
- **Root cause 2 (shading_mode delivery)**: code toggled `camera.shading_mode=2` before the wireframe pass and restored it after. `queue.submit()` batches ALL `write_buffer` calls to execute before ANY render pass, so the restore overwrote `2` before the GPU read it — wireframe pass always saw the restored value.
- **Fix**: added dedicated `wireframe_cam_buffer` + `wireframe_cam_bind_group` in `lib.rs` with `shading_mode=2` permanently baked in, updated per-frame in `update_camera()`.
- **Intermediate result**: gold PolygonMode::Line wireframe worked but showed ALL triangle edges including internal diagonals + back faces through geometry. Not the desired Houdini-style silhouette.
- **Final fix**: wrote `shaders/outline.wgsl` — normal-expanded vertex shader (clip-space expansion for constant screen-pixel width) + solid orange-gold fragment. Pipeline changed to `PolygonMode::Fill`, `cull_mode: Front` (back faces only), `depth_compare: LessEqual` with no bias. Back faces that protrude beyond the original mesh are the only ones that pass depth test → clean silhouette rim. File: `crates/bif_viewport/src/shaders/outline.wgsl`.

### Viewport ↔ tree selection sync

- **Gap 2**: `PrimSelected` handler set `selection.selected_prim_path` but not `selection.scene_browser_state.selected_path` — two separate selection stores that were out of sync. Added `scene_browser_state.select(&prim_path)` + `expand_to_path(&prim_path)` in the handler so viewport clicks auto-expand collapsed branches to reveal the target row.

- **Gap 4**: viewport → tree direction emitted the synthetic path which never matched any real USD tree row. Added `denormalize_synthetic_path()` helper that strips `/BIF/` prefix + numeric `/{idx}` suffix before emitting.

Added viewport bounds guard at the top of `select_at_screen` to early-return on UI panel clicks.

## Learnings

- **wgpu `queue.write_buffer` ordering**: all pending writes execute before any encoder commands on submit. You cannot toggle uniform state "between render passes" in the same encoder — you need separate buffers/bind groups per value.
- **DX12 depth bias**: `constant * 2^-24` scaling makes small integer constants essentially zero. For coplanar wireframe overlays, either use `depth_compare: Always` or switch techniques (normal-expanded back-face silhouette is more robust anyway).
- **egui premultiplied vs unmultiplied**: `from_rgba_premultiplied` with raw (non-premultiplied) RGB values produces near-additive color — the alpha only controls how much of the BG shows through but doesn't scale the RGB. Always use `from_rgba_unmultiplied` when passing straight colors with alpha.
- **Silhouette outline via normal expansion**: render back-face-only (`cull_mode: Front`) of a vertex-shader-expanded mesh with `depth_compare: LessEqual`. Clip-space expansion (`clip.xy += normal * clip.w * size`) gives consistent screen-pixel width regardless of distance. No stencil buffer needed.
- **Path format mismatches**: when the USD loader leaves `inst.prim_path` empty, `resolve_prim_path` synthesizes `/BIF/{proto_name}/{idx}`. For USD files where proto_name is itself a USD path (e.g. `/lucy/geo/shape`), the result is `/BIF//lucy/geo/shape/0` — needs bidirectional normalization to match tree paths.

### Learnings

- **wgpu `PolygonMode::Line`** is NOT the right tool for Houdini-style selection outlines — normal-expanded back-face silhouette (`cull_mode: Front` + `depth_compare: LessEqual`) gives clean DCC-quality outlines without stencil buffers.
- **`queue.write_buffer` ordering** in wgpu: ALL writes execute before ANY render pass. You cannot toggle uniform state "between" passes in the same encoder — need separate buffers.
- **Houdini USD export MaterialX gap**: Houdini auto-generates UsdPreviewSurface preview shaders but only populates diffuseColor/roughness — NOT displacement, normal maps, etc. Must manually add or extend the bridge.
- **`Arc::make_mut`** is the idiomatic pattern for mutating shared data during a one-shot load pass (refcount=1 → pointer cast, no clone).
