## Key Finding

**Subdiv UVs are completely broken** — C++ bridge vertex-splits faceVarying UVs (modifying topology), but Embree subdiv path uses `vertices_orig` + original polygon topology. UV count mismatches position count → UVs skipped entirely. Fix requires: preserving raw faceVarying UV data in C++ bridge, adding Embree faceVarying topology FFI (`rtcSetGeometryTopologyCount`, `rtcSetGeometryVertexAttributeTopology`), and setting up dual topology in subdiv geometry.

## Learnings

- USD `DomeLight_1` is a distinct prim type in USD 25.11 — `IsA<UsdLuxDomeLight>()` does NOT match it. Separate `domeLight_1.h` header + `UsdLuxDomeLight_1` class required.
- Embree 4 supports faceVarying attributes via separate topology slots — topology 0 = vertex connectivity, topology 1+ = faceVarying index buffers.
- Feature-gating Embree was clean — 3 `#[cfg]` on module declarations + 2 on re-exports. No stub types needed since consumers (bif_viewport) always use default features.

### Item 5: FaceVarying UVs for Subdiv — DONE

Full pipeline across 12 files, 4 layers:

**Part A — C++ bridge:** Added `facevarying_uvs`, `facevarying_uv_indices`, `facevarying_uv_count` to `CachedMesh`. Before vertex split in faceVarying UV extraction, preserves raw UV values + indices when `is_subd`. Wired through `UsdBridgeMeshData` struct and `usd_bridge_get_mesh_data()`.

**Part B — Rust FFI:** New fields in `UsdBridgeMeshDataRaw` → `ffi_convert.rs` conversion → `UsdMeshData` → `Mesh` → `SubdivInfo` → `SubdivData`. Updated 6 test structs + 3 `SubdivInfo` constructors.

**Part C — Embree:** Added `rtcSetGeometryTopologyCount` and `rtcSetGeometryVertexAttributeTopology` FFI bindings. Subdiv UV setup now creates dual topology (0=vertex, 1=faceVarying), sets faceVarying index buffer on topology slot 1, maps UV attribute to topology 1. Falls back to per-vertex UVs when faceVarying not available.

**Part D (deferred):** CPU displacement for subdiv deferred — faceVarying UVs fix the primary texturing bug. True Embree displacement dicing (`rtcSetGeometryDisplacementFunction`) deferred to v0.14.0+.
