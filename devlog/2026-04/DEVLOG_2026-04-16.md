## Learnings

- **Inherent methods mask trait methods** when both share a name. `UsdStage` has inherent `get_prim_info(index: usize) -> UsdBridgeResult<UsdPrimInfo>` AND `impl PrimDataProvider` with `get_prim_info(path: &str) -> Option<PrimDisplayInfo>`. Calling `stage.get_prim_info(&str)` dispatched to the inherent method, tried to convert `&str` → `usize`, → E0308. Fix: use `get_prim_info_by_path` (inherent, `&str`-keyed) — avoids the trait-shadowing entirely.
- **cxx-qt `Pin<&mut Self>.rust_mut()` returns a bound requiring `mut`** at the let-binding site. `let r = self.as_mut().rust_mut(); r.field = ...` needs `let mut r = ...` or write via temporary. E0596 first time through.
- **cxx-qt bridge accepts `QString` by value in invokable params** (not `&QString`). Consistent with existing `on_stage_path_opened(path: QString)`.
- **`denormalize_synthetic_path` is crate-private** in `bif_viewport`. Inlined locally in `bif_qt::main_window` rather than expanding the public surface. Simple enough string manipulation that dup is cheaper than keeping visibility in lockstep.
- **`Renderer::scene` is directly assignable** — no custom reset path needed. `vp.renderer_mut().scene = SceneManager::new()` + `rebuild_pick_scene()` is the full teardown sequence, paired with `wait_for_gpu()` first for GPU-queue drain (same root cause as commit `d290c9d` fix).
- **DPR-aware pick coord choice made inside `RenderWidget::mousePressEvent`** rather than in the Rust invokable — keeps Rust signatures DPR-agnostic, one conversion point near the event source. This also matches how `resized(pixelWidth(), pixelHeight())` already emits physical pixels.

## Blockers / risks surfaced

- **Scene Browser tree walk is eager.** `rebuild_from_state` recursively calls `child_prim_count` + `child_prim_path_at` for every prim. Fine for `root.usda`; for 100K+ prim scenes we need `canFetchMore`/`fetchMore`. Depth capped at 64 to bound pathological nesting but not width. Flag for post-v0.15.
- **Attribute `value` is `format!("{:?}", ...)`-shaped inside the `get_prim_attributes` bridge** — fine for smoke, but large arrays render as `"(432 float3 values)"`-style summaries from the FFI side. Pretty-printing is a v0.16 concern.
- **Opinion dot uses strongest-layer (stack[0]) color** for every attribute row. USD's real per-attribute opinion resolution isn't wired; that requires the `opinion_traces` map from the egui `PrimProperties::from_display_info`. Defer to v0.16.
