## Learnings
- Code Reviewer agents lean toward "blocker" — verify line numbers and read the code before fixing. ~40% of this run's blockers were real ship-blockers; the rest were defensible-but-defer items.
- USD's `SdfLayer::TransferContent` is theoretically throw-capable via listener notifications and asset resolver paths, even when called on a scratch layer that already validated `ImportFromString`. The cheapest backup primitive is `ExportToString` → `std::string`, then re-import on catch — robust because it's serialization-form, not in-place mutation.
- A `catch (const std::exception& e)` is not enough at a C-ABI boundary when the underlying library (USD) throws non-`std::exception` types like `TfRuntimeError`. Add `catch (...)` for safety.
- The CMake C++ bridge rebuild is fast on incremental (~7s), so iterating on `usd_bridge.cpp` edits is cheap.
