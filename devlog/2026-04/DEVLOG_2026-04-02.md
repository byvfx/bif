## Goals

- Set up automatic markdown linting going forward

## What I Did

- Installed `markdownlint-cli` globally via npm
- Created `.markdownlint.json` at repo root with pragmatic rule disables:
  - MD013 (line length) — code blocks/tables make this impractical
  - MD024 (duplicate headings) — devlogs all share `## Goals`, `## Learnings` etc.
  - MD025 (single H1) — LinkedIn post uses `#hashtags`
  - MD033 (inline HTML) — site/ uses HTML
  - MD036 (bold-as-heading) — devlogs use `**Phase N:**` style throughout
  - MD060 (table pipe spacing) — pervasive cosmetic issue across many tables
- Created `site/src/.markdownlint.json` for mdBook-specific overrides (MD025, MD042)
- Auto-fixed all 235 .md files: blank lines around headings/fences/lists, trailing spaces
- Bulk-labeled 721 unlabeled fenced code blocks as `text` using a stateful Python parser
- Manually fixed MD001 heading jumps in `BIF_USD_WORKFLOW.md`, `ARCHITECTURE.md`, `UX_ARCHITECT_REVIEW.md`, `MILESTONES_HISTORY.md`
- Added `<!-- markdownlint-disable MD025 MD042 -->` to `site/src/SUMMARY.md` (mdBook format requires multiple H1s and empty links)
- Set up `pre-commit` framework (replaces bare git hook):
  - `markdownlint-fix` — auto-fixes then blocks if unfixable errors remain
  - `cargo fmt` — blocks commit if Rust code isn't formatted
  - Config committed to `.pre-commit-config.yaml` — contributors run `pip install pre-commit && pre-commit install`

## Issues Found

- First bulk-fix script (`^```\s*$`) incorrectly labeled closing fences as ````text` — broke document structure. Fixed with a stateful parser that tracks open/close state and only labels opening fences.
- `site/src/.markdownlint.json` cascade wasn't being picked up by markdownlint-cli — worked around with inline `<!-- markdownlint-disable -->` comment in SUMMARY.md.
- `core.hooksPath` was set in git config, blocking `pre-commit install` — unset it first.

## Learnings

- `markdownlint-cli --fix` is not idempotent on the first pass when files are also modified by closing-fence restoration — need two passes.
- Pre-commit framework (`pre-commit install`) won't work if `core.hooksPath` is configured globally.
- A simple regex for bare code fences will match both opening AND closing fences — need stateful parsing.
