## Addendum — vfx-code-reviewer pass on `v0.16.1-followups`

Ran the `vfx-code-reviewer` agent against the eight commits ahead of `main`. Triaged into Critical / Major / Minor with file:line refs and a ship-with-fixes verdict. Four action items resolved on top of the sweep:

- **C3 (cpp_bridge.rs:2264-2265):** `get_prim_attributes` was missed by the 1875485 `cstr(...)` centralization. It also returned `InvalidPrim` for a CString conversion error — semantically wrong; `InvalidPrim` is reserved across the file for "USD says no such prim", `InvalidPath` for FFI string conversion. Fix: route through `cstr(prim_path)?`. One-line diff. Behavior change is a no-op in practice (interior NUL in a path is essentially never going to happen), but error variant is now consistent.
- **C2 (tests/ffi_contract.rs):** Added `layer_save_error_message_pointer_is_reused_per_thread`. Mirrors the existing export-buffer invalidation test for the layer-save `error_buf` thread-local. Locks asset and working layers, fires two failing saves, asserts pointer reuse and content overwrite. Required adding the `usd_bridge_layer_set_permission_to_edit` and `usd_bridge_layer_save` extern declarations to the test's local FFI block.
- **M3 (main_window.rs:78, 102, 1534, 2200):** The 47c9bf9 commit covered two visible `match` sites but left four `.lock().ok()` chains silently swallowing poison. Extended to log via `inspect_err(|e| log::error!(...)).ok()`. `with_stage` and `with_scene_browser_provider` are general helpers reached by many callers, so logging here pays for itself by exposing the recovery scope of any poisoning incident.
- **M5 (property_inspector_widget.cpp):** Reviewer flagged five lambdas as potentially missing the `if (!state) return;` guard from 1607cf4. Audited each (587, 597, 606, 625, 650, 660) plus the shading-model `QTimer::singleShot` deferral at 419 — every site already has the guard. Reviewer was misled by diff-only context; the file is already correct.
