## What I Did

### Fix: STORAGE_BINDING crash on sRGB textures

- **Bug:** `upload_raw_texture` created sRGB textures as `Rgba8UnormSrgb` with `STORAGE_BINDING` usage — wgpu rejects this (sRGB formats don't support storage)
- **Crash trigger:** Loading Bark.png (4096x8192), downscaled to 1024x2048, hit GPU mipmap path
- **Fix:** `upload_raw_texture` now creates sRGB+mips textures as `Rgba8Unorm` (storage-compatible) with `Rgba8UnormSrgb` in `view_formats`
- **View fix:** Function returns `(wgpu::Texture, wgpu::TextureView)` tuple — creates view with explicit `Rgba8UnormSrgb` format for sRGB+mips case, so callers get correct sRGB hardware decode
- Both call sites (`create_gpu_textures_for_scene`, `upload_streamed_texture`) updated

### Visual Verification

- Loaded heavy USD scene — textures load in ~2s (was 125s)
- sRGB colors render correctly
- 79/80 viewport tests pass (1 known flaky: `test_should_restart_no_render`)
- Clippy clean, fmt clean

### Files Changed

- `crates/bif_viewport/src/texture_loader.rs` — `upload_raw_texture` returns (Texture, View), sRGB format logic

## Learnings

- wgpu `view_formats` allows creating views with different-but-compatible formats from the native texture format
- Must create explicit `TextureViewDescriptor` with `format: Some(...)` to use a view_format — `default()` always picks native format

### Fix: Textures persist from first USD load when loading second scene

- **Bug 1:** `add_prototype()` during scene merge dropped `material` field — `Prototype::new()` sets `material: None`
- **Bug 2:** `face_material_ids` (GeomSubset indices) not remapped after merge — pointed at wrong materials in merged list
- **Fix:** Full prototype clone preserves material; face_material_ids offset by `working_scene.materials.len()` before merge
- **Files:** `scene.rs` (+`add_prototype_full`), `scene_loader.rs` (merge loop rewrite)
