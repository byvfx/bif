## Session 2: Ivar Texture Loading Fix

### Duration

~1 hour

### Goals

- Fix black objects and wrong textures in Ivar renders (ALab scene)

### What I Did

Fixed 3 root causes of Ivar texture issues after per-material fix landed:

1. **Default material OOB (batch_render.rs):** `build_materials()` returned N materials but `triangle_material_ids` referenced index N (the default). Appended fallback DisneyBSDF at index N.

2. **Relative path resolution (disney.rs):** `from_material_with_textures()` passed raw paths to TextureCache — relative paths failed silently. Added `resolve_texture_path()` + `load_texture_logged()` matching viewport behavior.

3. **Per-instance material binding (mesh_data.rs + scene_loader.rs):** `combine_with_transforms()` now takes `instance_material_id`. Scene loader builds material_index_by_name early, passes per-prototype material ID. Removed post-fill hack.

4. **Safety (embree.rs):** `materials.len() - 1` → `materials.len().saturating_sub(1)`.

- 89 bif_renderer tests pass (4 new resolve_texture_path tests)
- 41 bif_math tests pass

### Learnings

- Viewport and Ivar had divergent material array conventions — viewport appended default, Ivar didn't
- Silent `.ok()` on texture loads made debugging impossible
