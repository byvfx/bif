## What I Did

### VFX Code Review Fixes

Ran vfx-code-reviewer on commit 2a53b19. Review found 1 critical, 4 important, 5 suggestion issues. Fixed all:

1. **`Fn`+`Mutex` → `FnMut` (critical)** — `SceneBuilderFn` wrapped `SceneBuilderData` in `Mutex` for interior mutation behind `Fn`. Switched to `FnMut` which is semantically correct (sequential per-frame calls, no concurrency needed). Eliminates `Mutex` overhead and poison panic risk.

2. **Shared `build_materials()` (important)** — Material construction was duplicated 4 times (`build_ivar_scene`, `build_ivar_scene_at_time`, `prewarm_ivar_materials`, `SceneBuilderData::build_scene_at_time`). Extracted to `batch_render::build_materials()`.

3. **Prewarm/build race (important)** — `build_ivar_scene()` could spawn redundant material load while prewarm was nearly done. Added 50ms `recv_timeout` before fallback.

4. **Index buffer validation (important)** — No bounds checking on Embree indexed path. Added upfront `log::warn` for OOB indices.

5. **Per-vertex UV/normal storage (suggestion)** — `from_indexed()` was expanding per-vertex data to per-triangle (~6x memory). Now stores per-vertex arrays and does index lookup in `hit()`.

6. **Deprecated → doc comments (suggestion)** — `#[deprecated]` on `new()`/`try_new()` was premature (internal API, sole consumer). Replaced with `/// Prefer from_indexed()...` doc comments.

7. **4 new tests (suggestion)** — Added `test_from_indexed_basic_triangle`, `test_from_indexed_shared_vertices`, `test_from_indexed_instanced`, `test_from_indexed_no_materials_error`. 84 total bif_renderer tests, all passing.

## Learnings
- `FnMut` is correct for sequential mutation; `Fn`+`Mutex` is an anti-pattern when there's no concurrent access
- Per-vertex storage with index lookup in hot path is fine — the index indirection is negligible vs memory savings
- `recv_timeout` is a clean way to handle "prewarm might be done" without blocking indefinitely
