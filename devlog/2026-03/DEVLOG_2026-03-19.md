## Goals
- Fix native instance material overrides (testballs.usda: 3 spheres all rendering with glass)

## What I Did
- **C++ bridge: Implicit geometry** — added `tessellate_sphere()` and `tessellate_cube()` in C++, dedup spheres by radius and cubes by size (not prim path), so same-radius spheres produce 1 mesh + N-1 native instances with `material_override_index`
- **C++ bridge: Lighting overhaul** — `get_light_attr()` helper for old/new USD schema compat, color temperature (Tanner Helland), leftHanded mesh orientation fix
- **Rust loader: Material override processing** — moved native instance loop after material binding, built bridge→scene material index lookup, clone-prototype pattern with `override_proto_cache` to avoid duplicates
- **Winding convention** — switched from CW to CCW throughout (primitives.rs, mesh.rs normals, C++ tessellation)
- **DomeLight** — auto-HDRI connection, Y-axis rotation extraction from transform
- **RectLight** — radiance-based emission (removed distance falloff), emit along local -Z
- **UI** — default sky gradient toggle checkbox, black background default

## Issues Found
- Original plan assumed C++ bridge was already producing native instances for implicits — it wasn't. Spheres with different prim paths weren't being deduped. Fixed by deduping by radius/size instead.
- Rough metal sphere renders differently from Karma — needs investigation (Ivar sample count, shading model, or property value differences)

## Learnings
- USD implicit geometry (UsdGeomSphere/Cube) needs explicit tessellation — no mesh data exists in the stage
- USD light attributes changed prefix between schema versions (bare name vs `inputs:` prefix)
- Rust-side mesh dedup by geometry hash can also cause material override issues for regular meshes (separate from implicit geometry) — noted for future fix
