## What I Did

### Per-Tile UDIM Loading (6 phases)
1. **Shared tile infrastructure** — Added `UdimTileInfo`, `UdimGridLayout`, `UdimTileSet` to bif_core with per-tile sampling (resolve tile from UV floor, sample with fract UV)
2. **CPU renderer integration** — `OpenPbrSurface` checks UDIM tile set before single texture for all 5 material slots
3. **GPU viewport loading** — `prepare_texture_placeholders` and `start_texture_loading_async` expand UDIM patterns into individual tile paths, allocate contiguous texture array blocks
4. **GPU types** — `UdimGpuMapping` struct, `MaterialGpu::from_material` uses `udim_map` for base index + grid metadata
5. **Shader** — Replaced atlas UV remapping with per-tile lookup: `textures[base_idx + row * cols + col]` with fract UV. Eliminated row-flip logic.
6. **Cleanup** — Removed atlas stitching, UDIM disk cache, scale_pixels_box, ClearUdimCache UI, serde_json dep, old atlas tests

### Key architecture decisions
- UDIM pattern maps to base_index in texture array; tiles occupy contiguous block at `base + row * cols + col`
- Missing tiles in sparse UDIMs get default white texture (placeholder stays)
- `UdimTileSet` in bif_core is UI-agnostic — individual tiles accessible via `get_tile(col, row)` for future material editor

## Learnings

- The row-flip logic in the old atlas stitcher was a source of bugs — per-tile eliminates it entirely
- Cargo.lock changes from adding then removing serde_json resolved cleanly
