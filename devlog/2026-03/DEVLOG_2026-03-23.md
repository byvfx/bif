## Issues Found
- MaterialX OpenPBR materials were silently falling through to defaults — only base_color texture worked
- .tx files incorrectly assumed linear by `is_linear_texture_path` — sRGB .tx textures would have wrong colors
- UDIM `<UDIM>` pattern paths passed to pre_warm/convert functions caused file-not-found errors

## Learnings
- OpenPBR Surface uses different input names than standard_surface (`base_metalness` vs `metalness`, `geometry_normal` vs `normal`)
- .tx files preserve source colorspace — OIIO reports `is_linear` from metadata, not extension
- `TextureCache::load()` takes `&mut self` preventing direct parallelization — pre-warm pattern (parallel I/O + sequential insert) works around this
