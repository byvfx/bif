## What I Did

### .tx Texture Cache (e40e083, 9c3dacc, 1d63661)

- Viewport .tx preference via `resolve_tx_path` in `load_raw_texture_with_depth`
- Auto background .tx conversion on scene load
- Parallel `convert_textures_to_tx` via rayon

- Code review fixes: .tx not always linear (sRGB .tx would be washed out), ClearTxCache missing base_dir, null prim guard in parallel mesh extraction, UDIM pattern skip in pre_warm

### MaterialX OpenPBR Import (786ade0)

- Diagnosed: all MaterialX materials only had base_color texture, everything else at defaults
- Root cause: C++ bridge only recognized `standard_surface`, not `ND_open_pbr_surface`
- Fix: extended `is_materialx_pbr_shader()` + node name searches + OpenPBR input name fallbacks (`base_metalness`, `geometry_normal`, `geometry_opacity`)

### Shading Normal AOV (786ade0)

- Added `shading_normal` to `Material` trait (default: geometric normal)
- `OpenPbrSurface::shading_normal()` calls `apply_normal_map`
- Full pipeline: AovData → BucketResultWithAovs → ExrOutput (Ns.X/Y/Z) + viewport AOV dropdown
- Box `BucketResultWithAovs` in `IvarMessage` for clippy large-enum-variant

### Blue Noise Investigation

- Confirmed: blue noise fully implemented and active (256x256 void-and-cluster texture, Cranley-Patterson rotation, user-selectable via `SamplerMode`)
- Applied to sub-pixel camera jitter only, not light/material sampling

## Issues Found

- MaterialX OpenPBR materials were silently falling through to defaults — only base_color texture worked
- .tx files incorrectly assumed linear by `is_linear_texture_path` — sRGB .tx textures would have wrong colors
- UDIM `<UDIM>` pattern paths passed to pre_warm/convert functions caused file-not-found errors

## Learnings

- OpenPBR Surface uses different input names than standard_surface (`base_metalness` vs `metalness`, `geometry_normal` vs `normal`)
- .tx files preserve source colorspace — OIIO reports `is_linear` from metadata, not extension
- `TextureCache::load()` takes `&mut self` preventing direct parallelization — pre-warm pattern (parallel I/O + sequential insert) works around this

## Next Steps

- Compare Normal vs Shading Normal AOVs to confirm normal maps work
- Benchmark ALab with .tx cache (272 textures)
- Test parallel UV on rt_base (335M verts)
