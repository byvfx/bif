# Development Log - 2026-03-11

## Goals

- Implement texture loading optimization plan (T1-T3)
- Reduce USD scene texture loading from 125s to <1s perceived

## What I Did

### Tier 1: Quick Wins

- **T1-A**: Disabled CPU mipmap generation for viewport path (`generate_mipmaps = false`)
- **T1-B**: Parallelized OIIO texture loading with `rayon::par_iter()` (was serial `iter()`)

### Tier 2: Eliminate Format Conversion

- **T2-A**: C++ OIIO bridge reads LDR textures (PNG/JPG/TGA/BMP/TIF) as `TypeDesc::UINT8` directly
  - Skips `float` allocation + per-pixel `float_to_u8` conversion for ~60% of texture load time
  - HDR/EXR/TX still use float path
- **T2-B**: Viewport uploads raw u8 RGBA directly to GPU
  - New `RawTexture` struct + `load_raw_texture()` for both OIIO and non-OIIO paths
  - `Rgba8UnormSrgb` GPU format handles sRGB→linear decode in hardware
  - Eliminated triple conversion: C++ float→u8, Rust u8→f32 (sRGB LUT), GPU f32→u8

### Tier 3: GPU Mipmaps + Async + Size Limit

- **T3-A**: GPU mipmap generation via compute shader
  - New `mipmap_downsample.wgsl` shader (box-filter 2x2 downsample)
  - `MipmapGenerator` compute pipeline, integrated into upload path
  - Uses `STORAGE_BINDING` + `Rgba8Unorm` view for sRGB textures
  - Only for textures ≥64px (skip dispatch overhead for small textures)
- **T3-B**: Async texture streaming
  - `prepare_texture_placeholders()` returns instant GpuTextureSet with pre-allocated indices
  - `start_texture_loading_async()` spawns rayon background thread
  - `poll_texture_loads()` called each frame, uploads completed textures + rebuilds bind group
  - Scene appears immediately with white placeholders, textures pop in over 1-2s
- **T3-C**: Viewport texture size limit
  - `DEFAULT_MAX_VIEWPORT_TEXTURE_SIZE = 2048`
  - `downscale_raw_nearest()` operates on u8 RGBA data
  - Applied in `upload_raw_texture()` as min(gpu_limit, viewport_limit)

## Learnings

- wgpu storage textures don't support `_Srgb` formats — need `view_formats` + explicit `Rgba8Unorm` views
- `textureLoad` in WGSL reads raw values regardless of sRGB format (no conversion)
- OIIO's `ImageInput::read_image` with `TypeDesc::UINT8` gives raw sRGB bytes for LDR — no linearization
- Bind groups in wgpu are immutable — must recreate after any texture view change
