## What I Did

### Fix 1: MAX_VIEWPORT_TEXTURES 128→512

### Fix 2: Ivar Per-Triangle Material IDs

- Post-fill in `scene_loader.rs` after `instance_material_ids` built — maps each instance's triangles to its resolved material
- Confirmed: 60 unique materials distributed across 2.5M triangles (was all-material-0)

### Fix 3: UDIM UV Transformation

- Added `udim_grid_cols/rows/min_col/min_row` to `RawTexture` and `TextureLoadMessage`
- `load_udim_atlas()` populates grid metadata from computed bounds
- `GpuTextureSet.udim_grid` HashMap stores per-texture grid info
- `MaterialGpu::from_material()` packs grid into `extra_indices[1..2]` (cols<<16|rows, min_col<<16|min_row)
- Shader computes `sample_uv` with UDIM atlas transform, uses for all texture lookups
- Material table rebuilt after UDIM textures stream in (grid info unavailable at initial build)

### VFX Code Review Fixes

- Shader unsigned integer underflow on out-of-range UVs — use signed math + clamp
- Filter index 0 from UDIM grid lookup (prevent accidental default texture match)
- Set `has_udim` flag only after successful upload (not before)

## Issues Found

- **Viewport walls see-through** — pre-existing back-face culling issue, not caused by changes
- **Ivar green tint** — pre-existing: TextureCache doesn't handle UDIM `<UDIM>` patterns
- Embree hit normals are unnormalized geometric normals (raw cross products) — not new

## Learnings

- UDIM UV math: atlas stitcher flips rows (row 0 = bottom in USD, top in pixel space), shader must mirror this
- wgpu binding_array size comes from `MAX_VIEWPORT_TEXTURES` constant — changing it propagates everywhere
- `combine_with_transforms` returns `None` for tri_mat_ids when all are 0 — subtle interaction with `unwrap_or_default()`
- Material table must be rebuilt after async texture streaming when UDIM grid info arrives

- C++ bridge: `UsdBridgeCameraProperties` struct + `usd_bridge_get_camera_properties()` reading focal_length, vertical_aperture, clipping_range at time code
- Rust FFI: `UsdBridgeCameraPropertiesRaw` + extern fn + public `CameraProperties` with `fov_y()` method

#### Fix 3: Ivar UDIM TextureCache

- `texture.rs`: UDIM grid metadata on Texture struct, `transform_uv()` for CPU sampling
- `texture.rs`: `load_udim_atlas()` with probe/downscale/stitch pipeline, memory caps

### Issues Found

- 2 pre-existing test failures in `usd::export` (NullPointer) — unrelated

### Learnings

- USD `rightHanded` orientation means CCW front faces — C++ bridge fan triangulation preserves USD winding
- FOV formula: `2 * atan(vertical_aperture / (2 * focal_length))` — USD stores physical lens params, not angle
- `GfVec2f` for clipping range — USD packs near/far into a single `clippingRange` attribute

### Issues Found

### Learnings

- USD GfMatrix4d::GetArray() is row-major; passing to glam's from_cols_array implicitly transposes — this is correct and consistent with column-vector convention
- Lock-free CAS patterns need CAS on the value being updated, not just the counter
- Arvo's AABB transform avoids 8 matrix-vector multiplies by working with columns directly
