## Goals
- Build headless A/B benchmark for SHARC radiance cache to measure speedup objectively

## What I Did
- Created `crates/bif_renderer/examples/cache_bench.rs`
  - Programmatic Cornell box (5 walls + light + 2 spheres, 12 tris)
  - 32 progressive 1-SPP passes, cache OFF then ON
  - Parallel bucket rendering via rayon (same as production)
  - Prints per-pass timing, cumulative hit rate, occupancy
- Ran benchmark in release mode

## Results
- Cache OFF: ~6ms/pass (201ms total)
- Cache ON: ~10ms/pass (327ms total) — **0.62x (slower!)**
- Hit rate: 5.1% after 32 passes, occupancy: 59%
- Cache overhead (hash + RwLock per bounce) dominates for trivial BVH

## Learnings
- SHARC cache has non-trivial per-ray overhead from sharded RwLock
- Simple scenes (12 tris) are too cheap for cache to break even
- Need complex geometry where BVH traversal cost >> cache lookup cost
- Hit rate limited by `min_samples: 4` — cells need many passes to become trusted

## Session 3 (~30 min)

### Goals
- Fix all 5 VFX code reviewer issues from deferred writes commit
- Replace deferred writes with lock-free atomics (read-lock was the real bottleneck)

### What I Did
- **Removed deferred writes:** `WRITE_BUFFER` thread_local, `flush_thread_writes()`, `deferred_writes` config, `RefCell` import — had 2 bugs (global buffer, clear doesn't drain) and solved wrong problem
- **Added `AtomicCacheBuffer`:** `UnsafeCell<Vec<CacheEntry>>` + per-field `AtomicU32::from_ptr()` accessors; f32 fields via `to_bits`/`from_bits`
- **Dual backend:** `lock_free: bool` config (default true); `Option<AtomicCacheBuffer>` vs `Option<Vec<RwLock<...>>>`; all public methods dispatch
- **Lock-free lookup:** direct index into flat buffer, per-field atomic loads, zero locks
- **Lock-free write:** CAS on `sample_count` as version guard — empty→claim (0→1), stale→reinit (old→1), active→EMA+CAS (n→n+1); failed CAS drops sample
- **Bench A/B/C:** OFF / RwLock / lock-free; removed flush timing; guarded median; energy divergence warning >20%
- **Tests:** 18 total — added `test_rwlock_insert_and_lookup`, `test_lock_free_lookup_and_write`, `test_lock_free_concurrent` (16w+8r), `test_lock_free_cas_contention` (16 threads same cell)
- All checks pass: build, clippy, fmt, 18/18 tests

### Learnings
- `AtomicU32::from_ptr()` (stable 1.75+) lets you create atomic views of `#[repr(C)]` struct fields without changing the struct layout — perfect for GPU-compatible buffers
- CAS-based writes with "drop on failure" is ideal for progressive caches — losing 1 sample in thousands is invisible
- Torn reads (r from update N, g from N+1) are bounded error in progressive rendering — no need for seqlocks
