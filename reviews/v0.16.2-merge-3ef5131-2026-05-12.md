## Top issues by severity

### High

1. **Zero-count relationship array still allocates and must be freed** — `cpp/usd_bridge/usd_bridge.cpp` (in `usd_bridge_get_prim_relationships`, around the new block: `auto* data = new UsdBridgeRelationshipData[count];`). When a prim has zero relationships, `count == 0`, and the function still does `new UsdBridgeRelationshipData[0]` (legal C++, returns a unique non-null pointer per the standard) and assigns it to `*out_relationships`. The Rust wrapper then either:
   - calls `usd_bridge_opinions_free`/`usd_bridge_free_prim_relationships` with `count == 0` -> `delete[]` on the zero-sized array works, OK
   - or skips the free if it short-circuits on `count == 0`, which **leaks** the zero-sized array.

   Verify the Rust side (`crates/bif_core/src/usd/cpp_bridge.rs` `get_prim_relationships` -> `convert_relationships_ptr`) always calls the free function regardless of `count`. If it currently does `if count == 0 { return Vec::new() }` before the free, that is a leak. Recommendation: in C++, early-return `*out_relationships = nullptr; *out_count = 0; return SUCCESS;` when `entries.empty()` — symmetric with `target_paths = nullptr` when `tc == 0`, and removes the entire class of caller-side bugs.

2. **`refresh_node` walks live state mid-traversal but only acts on empty children** — `crates/bif_qt/cpp/scene_browser_model.cpp` (the new `refresh_node(QModelIndex)`). The code only force-repopulates "fake-leaf" nodes (kids cached as zero, live state now reports non-zero). That is the documented narrow contract, and the inline comment says so. But it is invoked from `find_source_index_for_path` recursion — meaning it can fire `beginInsertRows`/`endInsertRows` mid-`rowCount` walk in the parent. Qt's `QAbstractItemModel` invariants forbid changing the row structure while a view (or proxy filter) is iterating. With `QSortFilterProxyModel` upstream, this can produce stale `QModelIndex` invalidation crashes on dirty stages with deep payload arcs that materialize children lazily.

   Recommendation: gate `refresh_node` to fire only outside the recursive search, e.g. queue it via `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` or do a "scan first, then refresh" two-pass. Add a stress test that picks a prim under a payload that resolves to >1 child after `load_payloads` (i.e. the exact case the fix targets).

### Medium

3. **`collect_invisible_ancestors` over-reports vs `MakeVisible`'s authored-only walk** — `crates/bif_viewport/src/selection_dispatch.rs` (new function near the bottom). The inline comment acknowledges this: composed visibility flags ancestors that compose to invisible via *pruning from a higher ancestor*, not just those with their own authored `invisible` opinion. UX consequence: status bar warns "also un-hiding: /A, /B" when actually only /A gets re-authored. On real production stages with deep model hierarchies (assembly -> component -> mesh, each with its own visibility from a different layer), the "+N more" can be misleadingly large. Acceptable for v0.16.2; flag for the FFI extension on `cache_prim_data` split (v0.17). Add a `// TODO(v0.17)` linking to the planned authored-only walk.

4. **`set_edit_target` failure path leaves working layer set but C++ stage edit target stale** — `crates/bif_qt/src/main_window.rs` (the rewritten `with_viewport_mut` block in the "edit_target_sync" path). On `set_edit_target` error, the closure returns `Some("edit target sync failed: {e}")` and the working layer is *still* updated on the renderer side. This means subsequent edits land on the new working layer (Rust view) but the C++ `UsdStage`'s edit target still points at the old layer — silent layer corruption if the artist saves. The status string surfaces it, but artists will not read every status message before pressing Ctrl+S. Recommendation: on sync error, also revert `state.set_working_layer` to keep Rust + C++ in sync, or escalate to a modal for this specific failure mode.

5. **USD bridge thread-safety contract is documentary only** — `cpp/usd_bridge/usd_bridge.cpp` (new doc-comment on `cache_prim_data`). Excellent that the invariant is now written down. But there is no `TF_VERIFY(thread_id == owner_thread)` runtime check. The `prims_cached` boolean is the gate, *not* a synchronization primitive — a second thread entering `usd_bridge_load_payloads` concurrently with another caller hits the unguarded `cache_prim_data`. The doc says v0.17 will add the check; until then, every async work item that touches a stage handle is a footgun. Audit `bif_viewport/src/scene_manager.rs` to confirm the `Arc<Mutex<UsdStage>>` is held across the FFI call (not just acquired and released around it).

### Low

6. **`save_as_roundtrip` test does not assert export round-trips composition arcs** — `crates/bif_core/tests/save_as_roundtrip.rs`. The test exports a layer with a single transform edit and reopens. It does not verify references, payloads, sublayers, or instancing survive the export. A real production "Save As" needs to confirm that composing layers are not flattened. Recommend adding one variant against `LayeredStageFixture` with a sublayer + reference and asserting the exported text contains the same composition opinions.

7. **`payload_root_scene_browser_populates_after_load` test cleans up with `let _ = std::fs::remove_dir_all(&dir);`** — `crates/bif_core/tests/edit_op_roundtrip.rs` (new test, last few lines). Silent best-effort cleanup. If the test fails before this line, the temp dir is leaked. Use `tempfile::TempDir` (already a dev-dep) for RAII cleanup, matching the pattern in `LayeredStageFixture`.

8. **`refresh_child_visibility` runs before `endResetModel`** — `crates/bif_qt/cpp/scene_browser_model.cpp` (in `on_state_revision_changed`). The comment correctly notes Qt must see fresh values before `endResetModel`. Good. But `refresh_child_visibility` walks the whole previously-populated subtree synchronously on every state revision — on a 100k-prim stage with the eye-icon toggled, this is O(populated nodes). Profile this; if it shows on a frame budget, switch to per-node `dataChanged` signals for the visibility column only, scoped to the affected subtree.

## VFX production patterns — does it stand up?

- **Deep composition arcs**: Save As exports the working layer only (`export_layer_as_string`), so it does *not* try to flatten — correct behavior, matches Katana/Houdini convention. Good.
- **Payloads**: The `load_payloads` re-cache fix is exactly right. Verify it also fires when payloads are loaded *incrementally* (per-prim `LoadPolicy::LoadWithoutDescendants`), not just the bulk `load_payloads()`. The diff only patches the bulk path.
- **Instancing**: `pick_instance_at` post-hit visibility filter via `all_prim_paths` is a smart workaround for the stale-BVH problem. But it does not handle native USD instancing (`instanceable = true`) — picking a hidden native instance still resolves to the prototype path. Out of scope for this merge; flag for v0.17 viewport perf milestone.
- **Edit targets across layer mute/unmute**: Root-layer mute rejection at the FFI is the correct defensive fix. Test coverage is adequate.
- **MakeVisible side effects**: USD-correct, surprising to artists from Katana background. Status-bar surface is good UX; consider a one-time tooltip / first-run hint explaining the behavior.
