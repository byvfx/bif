# Scene Browser

The scene browser displays a unified hierarchy that merges USD stage data with BIF-generated procedural prims. It is the primary navigation panel for artists working with scenes.

## Overview

When a USD file is loaded and procedural nodes (Scatter, PointInstancer, Primitive) generate additional content, both sources need to appear in a single tree view. The scene browser solves this by compositing the two data sources through a provider pattern.

## Key Types

### CachedSceneGraph

A cached tree representation of the USD prim hierarchy. Rebuilt on a dirty flag when the USD stage changes or nodes recompute.

- Stores the expanded USD stage tree as a Rust data structure
- Invalidated when: USD stage is loaded/reloaded, node graph evaluation produces new prims, stage edits occur
- Avoids repeated FFI calls into the C++ USD bridge for tree traversal

### ProceduralPrimKind

An enum for BIF-generated prims that don't come from USD:

- `ScatterPoints` — point clouds from the Scatter node
- `PointInstancer` — instance transforms from the PointInstancer node
- `Primitive` — procedural geometry (cube, sphere, etc.)

These prims are generated by node graph evaluation and need to appear alongside USD prims in the scene tree.

### CompositeProvider

The merge layer that implements `PrimDataProvider` and combines:

1. **USD stage tree** — prims from the loaded USD file(s), accessed via CachedSceneGraph
2. **Procedural prims** — generated by BIF's node graph evaluation

The CompositeProvider presents a single unified tree to the scene browser UI. When an artist expands a path in the tree, the provider resolves whether each child comes from USD or from procedural generation.

### PrimDataProvider Trait

The `PrimDataProvider` trait abstracts the data source for the scene browser:

```rust
trait PrimDataProvider {
    fn children(&self, path: &str) -> Vec<PrimInfo>;
    fn properties(&self, path: &str) -> Vec<PropertyInfo>;
    // ... other methods
}
```

This trait enables the CompositeProvider pattern and ensures the scene browser UI doesn't need to know whether data comes from USD or procedural sources.

## Pattern: Dirty-Flag Rebuild

The scene graph cache uses a dirty-flag pattern:

1. Node graph evaluation completes -> sets dirty flag
2. USD stage load/reload -> sets dirty flag
3. Scene browser checks dirty flag on frame tick
4. If dirty: rebuild CachedSceneGraph from current state, clear flag
5. If clean: render from cache (no FFI calls, no recomputation)

This avoids expensive USD traversal on every frame while keeping the tree current.

## Implementation Files

- `crates/bif_viewport/src/scene_browser.rs` — CompositeProvider, CachedSceneGraph, tree view UI
- `crates/bif_viewport/src/scene_loader.rs` — USD loading orchestration that feeds the cache

## Bidirectional Sync

The scene browser supports bidirectional selection sync with the viewport:

- Select a prim in the tree -> highlights in viewport
- Click an object in the viewport (ray picking) -> selects in the tree
- Select a node in the node graph -> highlights related prims in both tree and viewport

## Future: Layer Awareness

Per [[003-hybrid-usd-workflow|ADR 003: Hybrid USD Workflow]], the scene browser will gain layer-aware features in v0.14.0:

- **Layer color dots** — 6px colored dots next to each prim showing which layer has the strongest opinion
- **Layer stack tab** — a companion tab in the left dock showing the sublayer stack with eye/lock icons
- **Opinion indicators** — visual cues showing whether a prim's properties come from the active layer, a weaker layer, or are defaults
