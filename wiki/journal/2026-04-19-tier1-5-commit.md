# 2026-04-19 — Tier 1.5 commit + camera-picker implementation

## What happened

Short session: committed the Tier 1.5 per-attribute opinion color work that had been implemented but left uncommitted at the end of the last session. Then planned the camera-picker feature.

## Tier 1.5 — per-attribute opinion color

The property inspector previously showed the same winning-layer color for every attribute row — it used `selected_prim_stack_color_index_at(0)` (the strongest prim-level layer) for all rows regardless of which layer actually authored each attribute.

The fix: `selected_prim_attr_color_index_at(i)` calls `get_attribute_opinions(prim_path, attr_name)` per attribute, finds the entry where `is_winning == true`, and maps its `layer_identifier` to the palette color index. Each row now independently reflects its own authoring layer.

`get_attribute_opinions` wraps `UsdAttribute::GetPropertyStack` on the C++ side — already existed in `cpp_bridge.rs` from previous session work.

## Camera-picker — what exists

Before planning the camera-picker, the explore revealed much of the foundation is already in place:

| Already exists | Location |
|---|---|
| `CameraSource` enum | `bif_viewport/src/ivar_state.rs` |
| `OrthoPreset` (Top/Bottom/Front/Back/Left/Right) | `bif_math/src/camera.rs` |
| `ProjectionMode::Orthographic { ortho_size }` | `bif_math/src/camera.rs` |
| `sync_viewport_to_usd_camera(stage, path, time)` | `bif_viewport/src/lib.rs` |
| `UsdStage::get_camera_properties` + `get_camera_xform_at_time` | `bif_core/src/usd/cpp_bridge.rs` |

The gap is: no enumeration of UsdGeomCamera prims in the stage, no `on_select_camera` invokable in bif_qt, no Qt UI widget for the picker.

## Camera-picker — implementation

Implemented same session. Commit `c835eaf`.

### Enumeration — no new FFI

`UsdStage::list_camera_prims()` filters the existing `all_prims()` result by `type_name == "Camera"` on the Rust side. No C++ changes required — `UsdPrimInfo` already carries `type_name`.

### Renderer helpers

Three new methods on `bif_viewport::Renderer`:

- `apply_usd_camera(path)` — sets `CameraSource::UsdCamera`, calls existing `sync_viewport_to_usd_camera`. The sync function is self-contained (reads stage from `self.scene.usd_stage` internally), so bif_qt invokables don't need a stage reference.
- `apply_ortho_view(preset)` — positions camera along the preset axis at current orbit distance, sets `ProjectionMode::Orthographic { ortho_size: dist * 0.5 }`. Reuses existing `OrthoPreset::direction()` / `up()` methods from `bif_math`.
- `apply_free_fly()` — resets to `ProjectionMode::Perspective` + `CameraSource::Viewport`.

`pub use bif_math::OrthoPreset` added to `bif_viewport/lib.rs` so `bif_qt` (which depends on `bif_viewport` but not `bif_math` directly) can use the type.

### Animated cameras — free

The existing `animation.rs` frame-change path already re-syncs `selected_usd_camera` on every frame tick. Animated USD cameras just work — no extra wiring needed.

### Qt UI

`QComboBox` in the breadcrumb row of `window_builder.cpp`. Items: "Perspective" (key `"free"`) → separator → Top/Front/Right/Bottom/Back/Left (keys `"ortho:Top"` etc.) → optional separator + USD camera leaf names (keys `"usd:/full/path"`). Repopulates on `camera_list_revisionChanged`. `on_select_camera` invokable dispatches by key prefix.
