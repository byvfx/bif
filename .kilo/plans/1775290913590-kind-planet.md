# BIF Architecture Review - Senior Architect Assessment

**Date:** 2026-04-04
**Codebase:** ~48,600 LOC Rust, 7 crates, 516 tests (#[test] count)
**Status:** v0.13.0-dev (Pipeline Foundation)

---

## Executive Summary

BIF is a well-structured VFX DCC project with clean crate boundaries and no circular dependencies. The architecture is **appropriate for a single-developer project** but shows strain from organic growth. Key technical debt items are **already documented** in `ARCHITECTURE_REFACTORS.md` but implementation lags documentation.

**Overall Grade: B+** — Good foundation, clear path forward, execution needed.

---

## Strengths

| Area | Assessment |
|------|------------|
| **Dependency Graph** | Clean: math → core → renderer → viewport → viewer. No cycles. |
| **Crate Separation** | Math is pure leaf. Core handles USD. Renderer is CPU-only. Viewport is GPU+UI. |
| **Feature Flags** | Clean passthrough (oiio/oidn). UI degrades gracefully without them. |
| **Process Isolation** | bif_maketx as subprocess prevents OIIO crashes from taking down main app. |
| **Event-Driven Design** | Node graph uses 17 event types → testable, undo support, clear audit trail. |
| **FFI Bridge** | Phase 1 split complete: ffi_raw.rs (925 LOC), ffi_convert.rs (1464 LOC), cpp_bridge.rs (1587 LOC). |
| **Testing** | 516 tests (actual #[test] count), strong assertion density (~3.3 per test). |

## Critical Issues

### 1. God Object: `Renderer` (bif_viewport/src/lib.rs:172)

**50+ fields** spanning 7 domains:
- GPU state (device, queue, pipelines, buffers)
- Camera, materials, textures
- UI state (egui, FPS, layout)
- Ivar integration
- Scene data, node graph context
- Selection, timeline, environment, lights
- Picking, point preview, curve preview, async channels

**Impact:** Hard to test, hard to reason about, couples rendering to UI to scene management.

**Status:** Documented in ARCHITECTURE_REFACTORS.md Phase 5. **Deferred.**

**Recommendation:** Accept for v0.13.0-v0.14.0. Decompose in v0.15.0 (Qt migration) when Renderer gets rewritten anyway.

---

### 2. God Enum: `SceneNode` (bif_viewport/src/node_graph/mod.rs:192)

**200+ line enum** with 11 variants. Adding a node requires changes in:
1. `SceneNode` enum definition
2. `NodeGraphEvent` (potentially)
3. `handle_node_graph_event()` — 17 arms
4. `evaluate_node()` 
5. UI code in `viewer.rs`

**Impact:** High friction for extending the node graph.

**Recommendation:**

| Option | Effort | Benefit |
|--------|--------|---------|
| **A. Keep as-is** (Recommended for now) | None | Works, Qt migration will reshape this |
| B. Trait-based nodes (`Box<dyn Node>`) | 2-3 weeks | Clean extension, but significant refactor before Qt |

Defer to post-Qt. The node graph will change significantly when porting to Qt anyway.

### 3. Untested Critical Paths

| File | LOC | Tests | Severity |

## Medium Issues

### 6. Feature Escalation in bif_viewport

bif_viewport depends on bif_renderer for:
- Ivar display (CPU path tracer → GPU texture)
- Embree pick scene
- OpenPBR materials

**Impact:** GPU viewport pulls in full CPU renderer.

**Recommendation:** Consider extracting picking to bif_core. Defer to post-v0.15.0.

---

### 7. Test Architecture Gaps

| Gap | Impact |
|-----|--------|
| No `#[should_panic]` tests | Error paths untested |
| No `#[ignore]` tests | No slow integration test markers |
| No `tests/` directories | All inline unit tests, no integration suite |
| No test fixtures directory | Test data inline or scattered |

**Recommendation:** 
- Add `#[should_panic]` tests for error handling paths
- Create `tests/` directories for integration tests
- Add `#[ignore]` for slow USD operations

## Architectural Alignment with Roadmap

### v0.13.0 (Current) → v0.14.0 (Layer-Aware Stage)

**What's needed:**
- USD layer stack queries (FFI expansion)
- Payload load/unload
- Opinion inspector

**Architecture readiness:** FFI bridge (Phase 1 done) supports this. Node graph will need new node types (Layer Stack, Layer Isolation).

### v0.15.0 (Qt Migration)

**What's needed:**
- Port all UI from egui to Qt
- T-layout implementation
- Viewport stays wgpu-based

**Architecture impact:** Major rewrite of bif_viewport. **This is the natural point to decompose Renderer.** The God Object and God Enum issues can be addressed during port.

### v0.16.0 (Edit Operations + Save)

**What's needed:**
- EditOperation enum with `to_usda()`
- Undo/redo for authoring
- Save to layer file

**Architecture readiness:** Event-driven node graph supports this. Need to add operation nodes (orange) alongside composition nodes (blue).

## Crate Evolution (Long-term Target)

```
Current:                           Future:
bif_math (leaf)                    bif_math (primitives)
bif_core (USD + scene + textures)  → bif_scene (Scene, Prototype, Instance)
                                   → bif_usd (USD I/O, composition)
bif_renderer (CPU path tracer)     bif_render_cpu (Ivar)
bif_viewport (GPU + UI + nodes)    → bif_render_gpu (wgpu viewport)
                                   → bif_ui (panels, node graph)
bif_viewer (entry)                 bif_app (application, config)
bif_maketx (tool)                  bif_tools (maketx, perf, utilities)
```

**Rationale:** Cleaner boundaries for:
- Testing scene logic without USD
- Using GPU viewport without UI (headless batch render)
- Replacing egui with Qt without touching renderer
